第 1 周：数组与链表

1. 内存布局 — 所有数据结构的物理基础

计算机内存是一个巨大的字节格子阵列。每个格子有唯一地址 (address)，你的变量就存在这些格子里。理解这点，数组的 O(1) 和链表的不能随机访问才有物理直觉。

数组：地址 = 基址 + i × 元素大小 → O(1) 随机访问 | 链表：必须从 head 顺 next 走 → O(N) 查找
💡 核心直觉
数组 O(1) 的本质：元素连续存储，地址可以算出来（基址 + i × 元素大小 = 一次乘法和一次加法）。
链表不能 O(1) 的本质：节点在内存里随机分布，没有固定的地址偏移规律，必须顺着 next 一个个找。
📖 建议翻阅原书
§1.1.5 (p.10-11) 数组基础，§1.4.9 (p.126-129) 内存使用。书上图 1.1.2 更精确展示了数组内存布局。

2. 数组 — 连续内存的威力与局限

数组是最基本的数据结构：固定大小的连续内存块，存同类型元素。创建时就定好大小，之后不能改。一行代码就能访问任意位置，但你得提前知道要存多少数据。

为什么数组的元素类型必须相同？因为随机访问靠"基址 + i × 元素大小"这个公式。如果元素大小不统一，公式就失效了。Python 的 list 虽然可以存不同类型的元素，但它的底层存的是对象引用 (reference)，引用的大小是固定的（8 bytes in 64-bit）。

操作复杂度原因
Access by index a[i]O(1)地址直接计算：基址 + i × sizeof(element)
Search (unsorted)O(N)最坏情况需要检查每个元素
Insert at end (有空间)O(1)直接写入下一个空位，size 加 1
Insert at front / middleO(N)插入点右侧所有元素必须向右移动一位
Delete at front / middleO(N)删除点右侧所有元素必须向左移动一位

为什么中间插入/删除是 O(N)？想象一排人坐在电影院座位上。要在第3个位置加一个人进来，第3位及之后的所有人都要站起来集体右移一个位置。如果 N=10000，那就得移动 9997 个人。

3. Resizing Array — 让数组"假变长"

Java 的 ArrayList、Python 的 list 看起来可以无限添加元素 — 底层都是 Resizing Array。核心思想：满了就分配更大的数组，把旧数据拷过去。

均摊每次 O(1) 换个视角：每个元素平均被"拷贝"2次（插入时1次 + resize时平均1次），所以 append 均摊成本是 2 次操作 = O(1)
🐍 Python 实现 — DynamicArray
class DynamicArray:
    def __init__(self):
        self.data = [None] * 1       # 初始容量 = 1
        self.size = 0                 # 当前元素个数
    def append(self, value):
        if self.size == len(self.data):
            self._resize(2 * len(self.data))   # 满了就翻倍！
        self.data[self.size] = value
        self.size += 1
    def _resize(self, cap):
        new = [None] * cap
        for i in range(self.size): new[i] = self.data[i]
        self.data = new

4. 链表 — 不靠连续内存

链表的每个 Node 有两部分：数据 (item) + 指向下一个 Node 的引用 (next)。因为不要求连续内存，插入删除不需要搬动其他元素 — 改两个指针就行。

链表中"插入删除 O(1)"的精确含义：前提是你已经有一个指向插入/删除位置的引用（比如 cur 指针）。如果你还没有这个引用，需要先从 head 遍历过去 — 这一步本身就是 O(N)。所以严格描述是：已知位置指针时，插入/删除是 O(1)；未知位置时，需要 O(N) 遍历找到位置。

🐍 Python — 单链表
class Node:
    def __init__(self, item):
        self.item = item; self.next = None

class LinkedList:
    def __init__(self):
        self.head = None; self._size = 0

    def prepend(self, item):           # O(1) — 头部插入
        node = Node(item)
        node.next = self.head
        self.head = node; self._size += 1

    def append(self, item):            # O(N) — 尾部插入，要遍历到末尾
        node = Node(item)
        if not self.head: self.head = node
        else:
            cur = self.head
            while cur.next: cur = cur.next
            cur.next = node
        self._size += 1

    def delete(self, item):            # O(N) — 按值删除
        if not self.head: return
        if self.head.item == item:
            self.head = self.head.next; self._size -= 1; return
        cur = self.head
        while cur.next:
            if cur.next.item == item:
                cur.next = cur.next.next  # 跳跃过被删节点
                self._size -= 1; return
            cur = cur.next

5. 数组 vs 链表 — 选哪个？

维度数组链表
内存布局连续，一次性分配分散，按需分配
随机访问O(1)O(N)
头部插入/删除O(N)O(1)
尾部插入O(1)*O(N) / O(1)†
中间插入（已知位置）O(N)O(1)
额外内存0（仅数据）每元素 +8~16 bytes
CPU Cache极好（顺序预取）差（cache miss 频繁）

* 有空间时 O(1)，需 resize 时均摊 O(1) | † 单链表 O(N)，带 tail 指针的双链表 O(1)

💡 现实中的选择
理论复杂度上链表插入更快，但现实中数组往往更快：CPU 从内存取数据时，不是只取你请求的那个字节，而是取一整块 cache line (64 bytes)。数组的连续存储使得下一次访问的数据大概率已在缓存中；链表的节点散落各处，几乎每次访问都是 cache miss。这就是为什么 ArrayList 通常比 LinkedList 实用的原因。

第 2 周：栈、队列与 Union-Find

1. 栈 (Stack) — LIFO

Last In, First Out — 像一叠盘子，只能动最上面那张。

🐍 Python Stack
class Stack:
    def __init__(self): self.items = []
    def push(self, item): self.items.append(item)
    def pop(self): return self.items.pop()
    def peek(self): return self.items[-1] if self.items else None
    def is_empty(self): return len(self.items) == 0

函数调用栈是怎么工作的？

这是栈最重要的实际应用。当你调用 f(x) 时：

Step 1 把当前函数的返回地址（执行完后去哪）压入 call stack
Step 2 把 f 的参数 x 压入 call stack
Step 3 把控制权交给 f，f 执行
Step 4 f 返回时，从 call stack 弹出返回地址，跳回去

递归就是反复调用自己 → 反复压栈 → 当递归太深（如 N=10000 层的递归）→ 栈溢出 (Stack Overflow)。这就是为什么 deep recursion 危险。

其他应用：Undo/Ctrl+Z 撤销、括号匹配 (LeetCode #20)、表达式求值 (Dijkstra 双栈算法，原书 p.80)。

2. 队列 (Queue) — FIFO

First In, First Out — 像排队买奶茶。

🐍 Python Queue（链表 + 双指针）
class Queue:
    def __init__(self):
        self.head = self.tail = None; self._size = 0
    def enqueue(self, item):
        node = Node(item)
        if not self.tail: self.head = self.tail = node
        else: self.tail.next = node; self.tail = node
        self._size += 1
    def dequeue(self):
        if not self.head: raise IndexError
        val = self.head.item
        self.head = self.head.next
        if not self.head: self.tail = None
        self._size -= 1; return val

3. 背包 (Bag)

无序集合。只能 add()、不能删除、可以遍历。语义上最弱 → 给了实现最大的优化自由度。允许重复（区别于 Set）。

4. Union-Find — 动态连通性

支持 union(p,q)（合并两个连通分量）和 connected(p,q)（查询是否连通）。应用：社交网络好友圈、电路连通性、图像分割、Kruskal 最小生成树。

UF 四种实现递进

版本核心findunion
Quick-Find同分量 id 相同O(1)O(N)
Quick-Union组织成树，id 存父节点O(h)O(h)
Weighted QU小树挂大树，h ≤ log NO(log N)O(log N)

Weighted QU 为什么树高 ≤ log₂ N？

每次 union 都是小树挂大树。一个小树中的节点，它的深度会增加 1，而它所在的树的大小至少翻倍。一个节点所在的树最多翻倍 log₂ N 次（因为不能超过 N）。所以深度 ≤ log₂ N。

Path Compression 更进一步：find 时把路径上的节点直接挂到根下。代码只需一行：parent[p] = parent[parent[p]]。加上后，amortized 复杂度是 inverse Ackermann 函数 α(N)，对所有实际 N 值 ≤ 5，基本上就是常数。

🐍 Weighted QU + Path Compression
class UF:
    def __init__(self, N):
        self.parent = list(range(N)); self.size = [1]*N; self.count = N
    def find(self, p):
        while p != self.parent[p]:
            self.parent[p] = self.parent[self.parent[p]]  # path compression
            p = self.parent[p]
        return p
    def union(self, p, q):
        rp, rq = self.find(p), self.find(q)
        if rp == rq: return
        if self.size[rp] < self.size[rq]:   # small hangs on big
            self.parent[rp] = rq; self.size[rq] += self.size[rp]
        else:
            self.parent[rq] = rp; self.size[rp] += self.size[rq]
        self.count -= 1

1. Order of Growth — 算法效率的通用语言

N 很大时，性能由最高次项决定。核心问题不是"这个算法跑多少秒"，而是 N 翻倍时，运行时间怎么变？

增长阶名称N翻倍时...N=1000N=1M典型例子

💡 一眼记住
N 从 1000 → 10000 (×10)：O(N²) 算法慢 100 倍，O(N log N) 只慢 ~13 倍。这就是为什么大数据量下算法选择比硬件重要得多。

2. Tilde Notation (~)

忽略低阶项和常数系数，只保留最高次项。和 O 的区别：~ 保留了常数因子。比如 selection sort 的比较次数是 ~½N²，insertion sort 平均是 ~¼N²，我们能看出后者约快一倍；但用 O，两者都是 O(N²)，看不出这个差距。

Tilde 的使用方法：写出精确的 cost model 表达式（比如每次比较算 1 次操作），然后取最高次项。如果算法有 ~2N² + 3N + 10 次操作，tilde 就是 ~2N²。

3. Doubling Ratio — 实验推断增长阶

最实用的实验方法，不需要读懂数学推导就能用：

① 测 T(N) 的运行时间
② 测 T(2N) 的运行时间
③ 算 ratio = T(2N) / T(N)
④ 如果 ratio ≈ 1 → O(1) 或 O(log N)
④ 如果 ratio ≈ 2 → O(N) 或 O(N log N)
④ 如果 ratio ≈ 4 → O(N²)
④ 如果 ratio ≈ 8 → O(N³)

实战技巧：写一个测试脚本，对 N = 1000, 2000, 4000, 8000, 16000 各跑 3 次取平均，打印每次的 ratio。ratio 会趋近对应的增长阶倍数。如果 ratio 在波动或下降，说明 N 还不够大。

4. Amortized Analysis — 偶尔贵 ≠ 一直贵

有些操作大多数时候便宜，偶尔贵。我们不关心单次最坏情况，而关心一系列操作的总成本除以操作次数。

resize 的 cost 是 1, 2, 4 — 指数增长但发生频率指数递减。总拷贝 = N-1 ≈ O(N)，均摊 O(1)。

5. 内存模型

Java 64-bit JVM：int=4B, double=8B, char=2B, reference=8B, object overhead=16B, array overhead=24B。存 N 个 int：数组 ~24+4N bytes，链表每个 Node ~32 bytes → 内存差 ~8 倍。

第 4 周：散列表

核心思想：把 key 直接映射成数组下标，实现 O(1) 查找。Python dict、Java HashMap、数据库索引全基于此。

1. Hash Function — 把钥匙变成门牌号

散列函数 hash(key) 把任意类型的 key 映射为 [0, M−1] 的整数。三条要求：

① Deterministic — 同一个 key 永远产生相同的 hash 值
② Uniform — hash 值均匀分布在所有桶中。不 uniform → 某些桶太满 → search 变慢
③ Fast — hash 的计算速度要快，毕竟是 O(1) 操作的一部分

Java String.hashCode() 是怎么计算的？

这是一个经典设计，值得仔细理解：

public int hashCode() {
    int hash = 0;
    for (int i = 0; i < length(); i++)
        hash = 31 * hash + charAt(i);     // Horner's method
    return hash;
}
// 数学等价于: s[0] × 31^(n-1) + s[1] × 31^(n-2) + ... + s[n-1]

为什么是 31？ ① 质数 — 减少碰撞概率；② 31 × i = (i << 5) − i — 编译器可以优化为位运算，计算很快。这种用质数加权每个字符的技巧叫做 Horner's method（霍纳方法），是多项式求值的标准优化。

如何处理负的 hash 值？

Java 的 hashCode() 返回 int，可能为负。取模 hash % M 的结果也可能为负。正确做法：(hash & 0x7fffffff) % M — 先去掉符号位再取模，或者用 Math.abs(hash) % M（但要注意 Integer.MIN_VALUE 取绝对值会溢出）。

2. Separate Chaining（拉链法）

每个桶存一个链表的头。hash 冲突的 key 放同个链表里。search 时：hash 定位桶 → 在链表中顺序查找。如果 hash function 够均匀，每个链表长度 ≈ N/M = α。M 取质数有助于均匀分布。Java 的 HashMap 默认 M=16，load factor 0.75（到达时扩容）。

3. Linear Probing（线性探测）

⚠ 删除的坑！
线性探测 delete 不能简单置空。置空后 search 遇空就会终止，以为 key 不存在 — 但 key 可能在更右边。
正确做法：用标记位（lazy deletion）或把右侧连续 key 全部 rehash 重新插入。详见 §3.4.3。
🐍 Hash Table — Linear Probing
class HashTable:
    def __init__(self, M=16):
        self.M = M; self.keys = [None]*M; self.vals = [None]*M; self.N = 0
    def put(self, key, val):
        if self.N >= self.M // 2: self._resize(2*self.M)
        i = hash(key) % self.M
        while self.keys[i] is not None:
            if self.keys[i] == key: self.vals[i] = val; return
            i = (i+1) % self.M  # 线性探测
        self.keys[i] = key; self.vals[i] = val; self.N += 1
    def get(self, key):
        i = hash(key) % self.M
        while self.keys[i] is not None:
            if self.keys[i] == key: return self.vals[i]
            i = (i+1) % self.M
        return None  # 遇到空位 → key 不存在

4. Python dict 是怎么工作的？

底层是 open addressing hash table。Python 3.6+ 保证插入顺序。核心优化：

  • Compact dict：indices 数组和 entries 数组分开存，节省约 1/3 内存
  • Hash 优化：整数 hash(42) = 42（除了 -1 映射为 -2），避免重复计算；字符串用 SipHash
  • Resize：load factor > 2/3 扩容 ×2（比我们 0.5 更高，因为 Python 的实现更好）
  • Perturbation：用复杂的探测序列避免 clustering

第 5 周：初级排序与 BST

Selection Sort

每次从右边未排序区选最小的，放到左边已排序区的末尾。比较次数永远是 ~½N²（和输入无关），但交换只有 N 次。Not stable。

例：[4, 2, 7, 1, 3] → 找最小 1，和 4 交换 → [1, 2, 7, 4, 3]
→ 找最小 2，已经在正确位置 → [1, 2, 7, 4, 3]
→ 找最小 3，和 7 交换 → [1, 2, 3, 4, 7]
→ ... 完成。每次找最小都要扫描整个未排序区。所以比较次数是 N+(N-1)+...+1 = ~N²/2。
def selection_sort(arr):
    for i in range(len(arr)):
        min_i = i
        for j in range(i+1, len(arr)):
            if arr[j] < arr[min_i]: min_i = j
        arr[i], arr[min_i] = arr[min_i], arr[i]

Insertion Sort

像整理扑克牌：每次拿一张，和左边已排好的比，找到正确位置插入。最关键的属性是 adaptive — 对近乎有序的数据极快（best case O(N)），对随机数据 ~¼N²，对逆序 ~½N²。Stable。

例：[4, 2, 7, 1, 3] 拿 2，和 4 比 → 4 右移 → [2, 4, 7, 1, 3]
→ 拿 7，比 4 大，不动 → [2, 4, 7, 1, 3]
→ 拿 1，比 7 小 → 7 右移，比 4 小 → 4 右移，比 2 小 → 2 右移，到最前 → [1, 2, 4, 7, 3]
→ 为什么对近乎有序的数据快？ 因为大多数元素已经在正确位置，不需要移动。
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]; j = i-1
        while j >= 0 and arr[j] > key:
            arr[j+1] = arr[j]; j -= 1
        arr[j+1] = key

Shell Sort

多轮 insertion，gap 从大变小。gap 大时元素可以跨很远移动 → 快速消除大量逆序对。gap 缩到 1 时就是普通 insertion，但数组已经"大致有序"了 → 很快。好的 gap 序列：3x+1 (Knuth 推荐): 1, 4, 13, 40, 121, ...。精确复杂度仍未完全证明 — still an open problem。

4. Binary Search Tree

升序输出！BST 排序的原理 Pre-order: 根→左→右 8, 3, 1, 6, 10, 9, 14 Post-order: 左→右→根 1, 6, 3, 9, 14, 10, 8

BST 核心操作详解

Search：从根开始，key 小于当前 → 走左边，大于 → 走右边，等于 → 找到。每步排除一半子树（类似二分查找）。随机插入时树高 ~2 ln N ≈ 1.39 log₂ N。

Insert：和 search 一样走，走到空链接的地方就挂一个新节点。如果 key 已存在就更新 value。

Delete（Hibbard deletion，原书 p.259）：最复杂的操作。三种情况：① 无子节点 → 直接删；② 一个子节点 → 用子节点替换；③ 两个子节点 → 找右子树的最小节点（successor）替换被删节点，再递归删除 successor。

class BST:
    class Node:
        def __init__(self, k, v):
            self.key=k; self.val=v; self.left=None; self.right=None; self.N=1
    def __init__(self): self.root = None

    def put(self, key, val):
        self.root = self._put(self.root, key, val)

    def _put(self, node, key, val):
        if node is None: return self.Node(key, val)
        if key < node.key: node.left = self._put(node.left, key, val)
        elif key > node.key: node.right = self._put(node.right, key, val)
        else: node.val = val
        node.N = 1 + (node.left.N if node.left else 0) + (node.right.N if node.right else 0)
        return node

    def get(self, key):
        node = self.root
        while node:
            if key < node.key: node = node.left
            elif key > node.key: node = node.right
            else: return node.val
        return None

    def inorder(self):
        res = []; self._in(self.root, res); return res
    def _in(self, n, res):
        if n: self._in(n.left, res); res.append(n.key); self._in(n.right, res)
⚠ BST 退化的根本原因
插入 key 是升序或降序 → 所有节点只有右（或左）子树 → 树变链表 → search 从 O(log N) 退化到 O(N)。这就是 Phase 2 要学的红黑树 (Red-Black Tree) 要解决的问题：通过旋转和颜色约束保证树始终平衡。

第 6 周：归并排序与阶段总结

1. Divide and Conquer（分治）

分治是影响最深远的算法设计范式之一。三步：Divide（拆成同类型子问题，通常对半拆）→ Conquer（递归解决子问题，base case：足够小时直接解决）→ Combine（合并子问题的解）。Mergesort、Quicksort、FFT、Strassen 矩阵乘法都基于分治。

2. Merge 操作 — 合并两个有序数组

两个已有序的子数组 arr[lo..mid] 和 arr[mid+1..hi]，合并成一个有序数组：

① 拷贝到辅助数组 aux
② 双指针 i (左半起始) 和 j (右半起始)
③ 比较 aux[i] 和 aux[j]，较小者放入原数组，对应指针前进
④ 某半耗尽时，把另一半剩余元素直接拷过去
⑤ Merge 的关键性质：等值时取左边 → 保证稳定性

Top-Down vs Bottom-Up

Top-Down：递归分解 → merge。代码简洁，分治思想清晰。Bottom-Up：从 size=1 开始两两 merge → 每次翻倍 → 直到覆盖整个数组。不用递归（无 call stack 开销），天然适合链表排序。

🐍 完整 Mergesort
def mergesort(arr):
    aux = [0]*len(arr)
    def merge(lo, mid, hi):
        for k in range(lo, hi+1): aux[k] = arr[k]
        i, j = lo, mid+1
        for k in range(lo, hi+1):
            if i > mid:                  arr[k] = aux[j]; j += 1
            elif j > hi:                 arr[k] = aux[i]; i += 1
            elif aux[j] < aux[i]:        arr[k] = aux[j]; j += 1
            else:                        arr[k] = aux[i]; i += 1   # ≤ 取左 → stable
    def _sort(lo, hi):
        if hi <= lo: return
        mid = (lo+hi)//2
        _sort(lo, mid); _sort(mid+1, hi)
        if arr[mid] <= arr[mid+1]: return   # 已有序跳过merge
        merge(lo, mid, hi)
    _sort(0, len(arr)-1)
