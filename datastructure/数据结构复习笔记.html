Part 1 · 区间和查询 Range Sum Querying Oracle

1.1 问题描述

✏️ 问题

输入（Input）： \(n\) 个元素 \(a_1, a_2, \dots, a_n\)

请求（Request）： 提供一个 API calc(l, r)，返回

\(a_l + a_{l+1} + \cdots + a_r\)

即「第 \(l\) 个到第 \(r\) 个元素的区间和（range sum）」。

这个例子贯穿整讲：同样一个问题，用不同的数据结构去存数据，查询和预处理的成本完全不同。下面依次看三种方案。

1.2 朴素解法一：循环求和 Naive Solution

把元素存进数组 \(A[\ ]\)（\(a_i\) 就是 \(A[i]\)）。每次调用 API 时，用一个循环把区间里的元素加起来。

ALGORITHM calc(l, r)
  total ← 0
  FOR i ← l TO r DO
    total ← total + A[i]
  RETURN total
衡量指标朴素解法一
每次查询的加法次数最坏情况多达 \(n\) 次
存储一个大小为 \(n\) 的数组

1.3 朴素解法二：预计算所有区间 Naive Solution 2

注意到不同的区间一共有 \(n(n+1)/2\) 个（任选起点 \(l\) 和终点 \(r\ge l\)）。干脆提前把每个区间和都算好，存进表 \(ANS[l, r]\)。查询时直接查表。

ALGORITHM calc(l, r)
  RETURN ANS[l, r]
衡量指标朴素解法二
每次查询的加法次数0 次（直接查表）
存储一个 \(n \times n\) 的表
⚠️ 用空间换时间

解法二查询极快，但存储是 \(O(n^2)\) 级别——「时间（time）」和「空间（space）」之间出现了权衡。这正是数据结构要面对的核心矛盾。

1.4 前缀和数据结构 Prefix Data Structure

能不能既查询快、又省存储？答案是前缀和（prefix sum）：把「前 \(i\) 个元素的和」存在 \(PRE[i]\) 里。

📌 前缀和的定义

\(PRE[i] = a_1 + a_2 + \cdots + a_i \qquad (PRE[0] = 0)\)

查询时返回：

\(\mathrm{calc}(l, r) = PRE[r] - PRE[l-1]\)

为什么成立？

把 \(PRE[r]\) 拆成两段：

\(PRE[r] = \underbrace{a_1 + \cdots + a_{l-1}}_{=\,PRE[l-1]} + \underbrace{a_l + \cdots + a_r}_{\text{想求的区间和}}\)

于是 \(PRE[r] - PRE[l-1] = a_l + \cdots + a_r\)，正好是区间和。

ALGORITHM calc(l, r)
  RETURN PRE[r] − PRE[l−1]
衡量指标前缀和
每次查询的算术运算1 次减法
存储一个含 \(n+1\) 项的数组（含 \(PRE[0]\)）

1.5 隐藏成本：预处理 Hidden Cost: Preprocessing

只看「每次查询」是不够的——三种方案建数据结构（预处理）的成本完全不同。把隐藏成本摊开看：

方案预处理伪代码加法次数
朴素解法一 FOR i ← 1 TO n DO A[i] ← a_i 0 次（\(n\) 次赋值）
朴素解法二（直接构造） 三层循环：对每个 \(l, r\)，再循环 \(i\) 累加 \(n(n+1)(n+2)/6\) 次
朴素解法二（复用前一个答案） ANS[l, r] ← ANS[l, r−1] + A[r] \(n(n+1)/2\) 次
前缀和 PRE[i] ← PRE[i−1] + A[i] \(n\) 次 
前缀和预处理：
PRE[0] ← 0
FOR i ← 1 TO n DO
  PRE[i] ← PRE[i−1] + A[i]
🎯 结论

前缀和完胜：预处理只需 \(n\) 次加法、存储是线性的 \(O(n)\)，却能支持 \(O(1)\) 的查询。它用「一次预处理」换来「之后每次查询都极快」。

为什么解法二「复用前一个答案」比「直接构造」好？因为 \(ANS[l,r] = ANS[l,r-1] + A[r]\) 复用了刚算出的 \(ANS[l,r-1]\)，把最内层循环省掉了——避免重复计算是算法设计最常用的技巧之一。

1.6 更进一步：更新与更多查询 We Always Ask for More

前缀和虽好，但需求一变，它就可能不够用了。老师抛出两个「进阶需求」：

✏️ 需求升级
  • 数据会变（evolving data）：还要支持 update(i, x)，即 \(a_i \leftarrow x\)（改掉某一个元素）。前缀和一旦改一个元素，所有 \(PRE[i], PRE[i+1], \dots\) 都要跟着改。
  • 更复杂的查询（complicated queries）：比如改问区间乘积 \(a_l \times a_{l+1} \times \cdots \times a_r\)——前缀「和」就没法直接套用了。

⇝ 老师留了个悬念：后续课程会学到能处理这些问题的数据结构（如树状数组、线段树、平衡树等）。这正是这门课要展开的方向。

Part 2 · 从 Python/Java 到 C++ From Java/Python to C++

2.1 同一个算法，不同的职责划分

看一个最简单的任务：输入整数 \(n\)，输出 \(2n\)。算法几乎不变，变的是「程序员、编译器、运行时」三者的职责分工。

Python:
n = int(input())
print(2 * n)

Java:
import java.util.Scanner;
class Main {
  public static void main(String[] args) {
    Scanner input = new Scanner(System.in);
    int n = input.nextInt();
    System.out.println(2 * n);
  }
}

C++:
#include <iostream>
int main() {
  int n;
  std::cin >> n;
  std::cout << 2 * n << '\n';
  return 0;
}
✏️ 关键点

你早就知道怎么写这个程序；现在要学的是「如何把同一个意思表达给 C++ 编译器」。三种语言把这个简单任务背后的职责（类型检查、内存管理、执行时机）放在了不同的位置。

2.2 为什么学完 Python/Java 还要学 C++

Python、Java、C++ 在「责任（responsibility）」和「控制（control）」上做了不同的默认选择（default choices）。

以「往列表里加一个元素」为例：

Python:  a = []        ; a.append(x)
Java:    ArrayList<Integer> a = new ArrayList<>();  a.add(x);

C++ 会逼你追问这些被高层语言「藏起来」的问题：

  • 这个 API 隐藏（hide）了什么？
  • 元素在内存里是怎么排布（arranged in memory）的？
  • 可用空间用完时会发生什么？
  • 为什么在末尾插入通常很快，在开头插入通常很慢？
  • 扩容时要不要复制已有元素？
🎯 一句话

Python/Java 帮你做了很多决定；C++ 让你看清并自己决定这些细节——这正是学数据结构需要的视角。

2.3 C++ 与数据结构：抽象 ↔ 表示 ↔ 成本

📌 数据结构课问的三件事
  1. 这个 API 做什么？（abstract operation 抽象操作——程序应该完成什么）
  2. 数据怎么存？（concrete representation 具体表示——数据在内存里如何布局）
  3. 这个选择花多少代价？（time and space cost 时间与空间成本——需要多少运算和内存）

抽象操作（what the program should do）\(\longleftrightarrow\) 具体表示（how data is stored）\(\longleftrightarrow\) 时间与空间成本（what work and memory are required）

🎯 为什么是 C++

C++ 让我们把「操作」「表示」「实际成本」三者连起来看。高层语言（如 Python）把表示和成本都藏起来了，你很难体会到「换个数据结构」到底省了什么。

Part 3 · 语言观念的转变 Shifting Mindsets

3.1 高级语言 ≠ 面向对象 High-Level and Object-Oriented Are Different

概念含义例子
高级语言
high-level language		 用变量、循环、函数、容器来表达，而不必直接写机器指令 total += x 一句可能对应底层多次 load、add、store 操作
面向对象编程
object-oriented programming		 通过「对象」把相关的状态（state）和行为（behavior）组织起来，常用类（class）来描述 account.deposit(x) 让拥有余额的对象自己更新状态

三种语言的定位：

  • Python：面向对象是可选的、动态的；代码可以写在类外，名字通常指向对象。
  • Java：应用代码以类为中心；对象变量通常持有由 JVM 管理的引用。
  • C++：多范式（multi-paradigm）；代码可以写在类外，对象可以直接作为值存在，也可以间接访问。
✏️ 具体后果

一个独立的辅助函数在 Python 和 C++ 里很自然；Java 通常把它放进某个类里作为方法。高层抽象仍有真实的时间和内存成本；面向对象 ≠ 所有东西都得是类。

3.2 更多控制 = 更多责任 More Control Means More Responsibility

语言默认行为
Python通常隐藏静态类型、对象布局、内存管理的细节
Java让大多数类型显式，但 JVM 仍替你管理对象和内存
C++要求你理解对象如何被存储、复制、移动、销毁

一个「预览（preview）」，现在不要求背：

int x = 10;
std::cout << sizeof(x) << '\n';   // 查看一个对象的大小
std::cout << &x << '\n';          // 查看对象存放在哪里
std::vector<int> a;
a.reserve(1000);                    // 控制容器的预定容量
  • sizeof(x) —— 检查对象的大小
  • &x —— 观察对象的存储位置
  • a.reserve(1000) —— 控制容器的计划容量
🎯 三种语言一句话总结
  • Python —— 方便地表达想法（Express ideas conveniently）
  • Java —— 在受管运行时里安全地组织对象（Organize objects safely inside a managed runtime）
  • C++ —— 保留高层抽象的同时，控制表示和成本（Keep high-level abstractions while controlling representation and cost）

在 C++ 里，我们同时看到抽象、表示、操作成本和内存行为。

3.3 三种执行路径 Three Execution Paths

语言执行路径特点
Python 源码 → 由 Python 运行时执行 更多行为在程序运行时由运行时决定
Java 源码 → Java 字节码 → JVM 执行或即时编译（JIT） 字节码面向受管虚拟机，虚拟机可在执行中优化
C++ 源码 → C++ 编译器 → 原生可执行程序 编译器在执行之前解决更多问题，为目标机器生成代码
🎯 关键洞察

算法可以保持不变；语言改变的是「实现决策在哪里、什么时候做」。

Part 4 · 类型与变量 Types and Variables

4.1 类型成为程序设计的一部分 Types Become Part of Program Design

Python:
x = 10
x = "hello"      # 同一个名字可在不同时刻绑定不同类型的对象

C++:
int x = 10;
📌 int 不只是多写一个词

声明 int x = 10; 时，编译器因此知道：

  • \(x\) 应该存什么（整数）
  • 需要多少空间
  • 哪些操作合法
  • std::cin 知道该解析成整数
  • 很多错误能在执行前就被查出
int x = 10;
x = "hello";   // 在执行前就被拒绝（rejected before execution）
               // 第二次赋值违反了 int 声明的「契约」
🎯 一句话

在 C++ 里，类型不是语法负担，而是程序员交给编译器的一份「契约（contract）」。（从 Java 转来的同学对静态类型已不陌生；C++ 进一步把存储、复制、对象生命周期也纳入同一份类型决策。）

4.2 变量在不同语言里的含义 Variables Mean Different Things

语言变量的含义b = a 的效果
Python变量更像指向对象的「名字」b = a：a、b 通常指向同一个列表
Java基本类型变量存值；对象变量通常存引用List b = a：两个变量通常指向同一个对象
C++很多变量就是对象本身，有明确的值语义vector b = a：通常新建一个独立的 vector
✏️ 赋值后执行 b[0] = 99 会怎样？
  • Python / Java：a[0] 通常也跟着变——因为两个名字指向同一个对象。
  • C++：a[0] 不变——因为 b 是独立的 vector。

⇝ 在 C++ 里，「赋值或传参时是否复制对象」既是正确性（correctness）问题，也是性能（performance）问题。

Part 5 · 第一个 C++ 程序 A Minimal C++ Program

5.1 最小 C++ 程序

#include <iostream>

int main() {
  int n;
  std::cin >> n;
  std::cout << n << '\n';
  return 0;
}

逐行拆解：

  • #include <iostream> —— 把标准输入输出（standard I/O）的声明提供给编译器。
  • int main() —— 定义程序从哪里开始执行。
  • std::cin —— 从标准输入读取；std::cout —— 写到标准输出。

5.2 程序结构与标准 I/O

语法含义
#include <iostream>作用类似「使用一个库」，但内部不同于 Python 的 import
int main()C++ 从独立的 main 函数开始；Python 可能从文件顶层执行；Java 从类里启动
{ } 花括号标记一个程序块（block）。Python 用缩进，Java 和 C++ 用花括号
std::cin >> n从标准输入读一个值到 n
std::cout << n << '\n'输出 n，然后一个换行
✏️ std:: 是什么意思？

一个实用的初步理解：「到 C++ 标准库的命名空间（namespace）里找」。using namespace std; 可以去掉这个前缀，但本课保持显式（keep it explicit）。

注：这些都是有意简化的初阶解释，预处理（preprocessing）和命名空间后面会讲得更精确。

5.3 熟悉的逻辑，新的语法 Familiar Logic, New Syntax

判断（decision）、循环（repetition）、状态（state）都没变；变的只是类型、花括号和输入输出语法。

选择 if：
Python:  if x > 0:
           positive += 1
Java:    if (x > 0) {
           positive += 1;
         }
C++:     if (x > 0) {
           positive += 1;
         }

循环 for：
Python:  for i in range(n):
           total += a[i]
Java:    for (int i = 0; i < n; ++i) {
           total += a[i];
         }
C++:     for (int i = 0; i < n; ++i) {
           total += a[i];
         }
✏️ 两个要点
  • 分支没变：测同样的条件、更新同样的状态；Java 和 C++ 只是加了括号、花括号和分号。
  • 循环更显式：Python 的 range(n) 把「初值、停止条件、步进」打包在一起；Java 和 C++ 把这三件事一一写出来。

Part 6 · 迁移清单与练习 Transfer Checklist & Practice

6.1 从 Python / Java 迁移清单

📌 从 Python 来

你已经会 if、for 和函数。到了 C++，要更早回答这些问题：

  • 这个变量的类型是什么？
  • 这个容器存什么类型？
  • 这个对象会被复制吗？
  • 这个对象活多久？
📌 从 Java 来

很多语法看起来眼熟，但 C++ 不是「少几个关键字的 Java」：

  • 并非所有东西都必须属于某个类
  • 对象常常直接作为值存在
  • 复制和销毁更显式
  • 没有一个 JVM 替你管理每个对象
🎯 共同的习惯

先说明程序是什么意思，再决定 C++ 如何表示数据、生命周期和操作（state → types → C++）。

6.2 练习：提炼算法 Practice: Extract the Algorithm

Python:
n = int(input())
positive = 0
for _ in range(n):
  x = int(input())
  if x > 0:
    positive += 1
print(positive)

面对这段 Python，先问六个问题：

  1. 程序维护了什么状态（state）？
  2. 每份状态可以是什么类型？
  3. 哪部分是循环？
  4. 哪部分是条件？
  5. 哪部分只属于 Python 的输入输出？
  6. 这个算法换成 Java 或 C++ 会改变吗？（不会，变的只是表达方式）
✏️ 迁移三步

保留算法 \(\longrightarrow\) 说清状态与类型 \(\longrightarrow\) 用 C++ 表达输入、循环、分支与输出

Part 7 · 总结 Summary

🎯 本讲两条主线

Part 1 · 程序骨架与编译执行 Default Set-up, Compilation & Execution

1.1 默认程序结构 Default Set-up

从今天起，除非特别说明，我们都假设程序是下面这个骨架：

Part 2 · 类型系统 Types

2.1 类型检查的时机 Type Checking at Different Time

同一段「把两个字符串相乘」的逻辑，在不同语言里错误暴露的时机完全不同：

Python:
print("Running...")
hello = "Hello "
world = "World!"
print(hello * world)     # 先打印 Running...，然后运行时出错

C++:
std::cout << "Running...\n";
std::string hello = "Hello ";
std::string world = "World!";
std::cout << hello * world;   // 编译期错误，程序根本无法启动
// 这个 C++ 例子还需要在 main() 上方 #include <string>
语言出错时机现象
Python运行时（runtime）Running... 先出现，随后字符串相乘抛出运行时错误
C++编译时（compile-time）程序无法启动
🎯 一句话

静态类型检查（static type checking）能在执行前就抓住许多错误。

2.2 静态类型绑定 Static Type Binding

Java 或 C++ 的变量有固定类型；Python 的名字可以被重新绑定到另一种对象。

Python:
x = 10
x = "hello"     // 允许：现在 x 指向一个字符串

Java:
int x = 10;
x = "hello";    // 拒绝：x 是 int

C++:
int x = 10;
x = "hello";    // 拒绝：x 是 int
📌 要点

值可以改变；声明出来的类型不会变。有些转换是允许的，但那不代表变量「换了类型」——它仍是原来的类型。

Part 3 · 变量与初始化 Variables & Initialization

3.1 声明、初始化、赋值 Declaration / Initialization / Assignment

概念代码含义
声明（declaration）int total;创建一个没有初始值的局部变量
初始化（initialization）int total = 0;创建一个带起始值的变量
赋值（assignment）total = 5; total = total + 2;更新已存在的变量；最终值是 7

我们通常用 =。此外 int x(5); 和 int x{5}; 也都能把 x 初始化成 5。

3.2 窄化转换：小括号 / = / 花括号 Narrowing Conversions

如果初始值是 5.5（而不是 5）会怎样？三种写法结果不同：

独立示例结果原因
int x(5.5);编译通过：x = 5丢弃小数部分
int x = 5.5;编译通过：x = 5发生同样的转换
int x{5.5};编译期错误花括号拒绝窄化转换（narrowing conversion）
⚠️ 注意

小括号和 = 允许截断（truncate），而不是四舍五入到最近的整数；编译器可能给出警告。

要零初始化，int total{0}; 和 int total{}; 都能从 0 开始。

3.3 未初始化的局部变量 Uninitialized Local Variables

int count;           // 不要读这个值
std::cout << count;

没有发生初始化。在 C++20 中读取这个局部 int 是未定义行为（undefined behavior）。

int count;           // 先赋值，再读
count = 0;
std::cout << count;  // 打印 0
🚫 铁律

永远不要假设未初始化的局部变量是 0！

程序可能看起来打印 0、打印别的值，或者在不同运行、不同编译器、不同编译设置、不同环境下表现各异——这些观察都不构成任何保证。

（全局变量和静态变量遵循不同的初始化规则；这条警告针对的是普通的局部变量。）

4.3 前缀与后缀自增 Prefix and Postfix Increment

两种形式都让 x 增加 1，但它们的表达式提供不同的值：

前缀：用新值
int x = 5;
int y;
y = ++x;    // x = 6, y = 6

后缀：用旧值
int x = 5;
int y;
y = x++;    // x = 6, y = 5
int x = 5;
std::cout << x++ << '\n';   // 打印 5，然后 x 变成 6
std::cout << ++x << '\n';   // 先增到 7，再打印
std::cout << x << '\n';     // 打印当前的 x
// 输出：5  7  7
✏️ 备注
  • 作为独立语句，++x; 和 x++; 对 int 效果相同。同样的区别适用于 --x 和 x--。
  • Java 有同样的区别；Python 没有自增运算符，用 x += 1。

4.4 预测值练习 Predict the Values

每个例子独立开始，问最后一条语句之后的值是多少：

int x = 3; int y;
y = x++ * 2;      // x = 4, y = 6

int x = 3; int y;
y = ++x * 2;      // x = 4, y = 8

int x = 3; int y;
y = x++;
y += ++x;         // x = 5, y = 8

int x = 3; int y;
y = x-- + 10;     // x = 2, y = 13
🚫 通用建议

让更新易于理解：用分开的语句，不要把对同一变量的多次修改塞进一个表达式。不确定某段代码会怎么表现，就不要写它。

✏️ 与 Python 的区别

Python 的 // 向负无穷方向向下取整；Python 的 / 是真除法：7 / 2 得 3.5。

4.7 得到浮点商 Getting a Floating-Point Quotient

把结果赋给 double 并不能改变一个已经发生过的除法。

int total = 7;
int count = 2;
double average;
average = total / count;          // 3.0
average = 1.0 * total / count;    // 3.5
average = total / (count * 1.0);  // 3.5
average = total / count * 1.0;    // 3.0
⚠️ 为什么最后一行是 3.0

在最后一行里，/ 和 * 从左到右结合：(total / count) * 1.0 把一个已经被截断成 3 的结果再转成 3.0。

结论：在除法发生之前，先让某个操作数变成浮点数。

Part 5 · 溢出与类型陷阱 Overflow & Type Pitfalls

5.1 有符号整数溢出 Signed Integer Overflow

假设是 32 位 int：其最大值是 2,147,483,647。

int x;
std::cin >> x;   // 输入 2147483647
x = x + 1;
std::cout << x;

数学结果是 2,147,483,648，但这个结果无法用 int 表示。在 C++ 里，有符号整数溢出是未定义行为（undefined behavior）。

语言 / 类型给 2,147,483,647 加 1
Python int2147483648 —— 整数可以增长
Java int−2147483648 —— 定义好的 32 位回绕
C++ 32 位 int没有保证的结果——甚至不保证崩溃
✏️ 为什么程序可能继续运行？

普通机器指令可能只保留低 32 位，未必抛出异常：

01111111 11111111 11111111 11111111   （2,147,483,647）
+ 1
10000000 00000000 00000000 00000000   （若按有符号 32 位解释为 −2,147,483,648）

这只解释了一种常见的观察结果，是硬件层面的示意，不是 C++ 对有符号溢出的有效规则。编译器可能假设有符号溢出永不发生来优化；换个编译设置可能得到不同结果——甚至没有有用的结果。在支持的编译器上，-fsanitize=undefined 能在运行时报告有符号溢出。

5.2 无符号回绕 Unsigned Arithmetic Wraps Around

与有符号溢出不同，无符号算术定义为模 \(2^w\)。对 32 位 unsigned int，模是 4,294,967,296。

// 超过最大值
unsigned int x = 4294967295U;
x = x + 1;
std::cout << x;   // 0

// 低于零
unsigned int x = 0;
x = x - 1;
std::cout << x;   // 4294967295
⚠️ 有符号 / 无符号混用很危险

无符号只是有更大的非负范围，不是算术错误的保护伞。

int a = -1;
unsigned int b = 1;
std::cout << (a < b);   // 0：false！

这里 a 在比较前被转换成 unsigned int。按 32 位示例，−1 变成 4,294,967,295。避免随意混用有符号和无符号。

5.3 先拓宽再运算 Widen Before the Operation

目标类型无法修复「计算它的表达式」里已经发生的溢出。

// 太迟了
int a = 100000;
long long square;
square = a * a;      // a * a 按 int 计算；10,000,000,000 放不下

// 用一个更宽的操作数
int a = 100000;
long long square;
square = 1LL * a * a;   // 1LL 是 long long，两次乘法都用更宽的类型

long long wide;
wide = a;
square = wide * a;      // 也是 10000000000
⚠️ 仍然要检查范围

即使 long long 也是有限的。先让一个操作数变宽，再运算。

5.4 布尔与字符算术 Boolean and Character Arithmetic

bool 和字符值可以参与整数算术。小的整数类型通常在运算前被提升（promote）为 int。

bool
bool ok = true;
std::cout << ok + 2;  // 3
ok = 7;               // true：任何非零值
// false → 0，true → 1

char
char digit = '7';
int value;
value = digit - '0';   // 7
// '0' 到 '9' 的编码是连续的

unsigned char
unsigned char b = 250;
std::cout << b + 10;  // 260：int 算术
b = b + 10;            // 4：存回 8 位
// 假设 8 位字节：260 % 256 = 4
⚠️ 三个提醒
  • 要看字符的数值码，用 ch + 0；std::cout << ch 打印的是字符本身。
  • Java 不允许布尔算术；Python 和 C++ 允许。
  • std::cin >> ch 读的是一个字符，不是数字：输入 12345 只存下 '1'，剩下 2345 未读。char 永远不会「扩展」。数值输入请用 int 或 long long（在其范围内）。

Part 6 · 布尔表达式与控制流 Boolean Expressions & Control Flow

6.1 短路求值 Short-Circuit Evaluation

关系与逻辑运算符：== != < <= > >= && || !

短路求值：先算左边，一旦结果已确定就停止。

// 逻辑与 &&
int d = 0;
bool result;
result = (d != 0 && 10 / d > 2);
// 左边是 false → 跳过右边，结果是 false
// 10 / d 根本不会执行，所以没有除以零

// 逻辑或 ||
int d = 0;
bool result;
result = (d == 0 || 10 / d > 2);
// 左边是 true → 跳过右边，结果是 true
// 10 / d 在这里也不会执行
✏️ 关键点

被跳过的表达式完全不执行——即使跳过的那一侧有 ++x，x 也不会被改变。

6.2 短路与程序员的责任 Short-Circuiting and Responsibility

这个数组有三个元素，合法下标是 0、1、2。

// &&：跳过不安全的数组访问
int a[3] = {10, 20, 30};
int i = 5;
bool found = ((0 <= i && i < 3) && a[i] == 20);
// i = 5：边界检查失败，所以 a[i] 被跳过
// i = 0：读到 10，found 为 false；i = 1：读到 20，为 true

// ||：故意触发失败
bool fail();   // 提供的辅助函数：报告错误并退出
bool valid = (0 <= i && i < 3);
valid || fail();
// i = 5：valid 为 false，fail() 运行并终止程序
// i = 1：valid 为 true，fail() 被跳过
⚠️ 责任边界

越界读取是未定义行为，不是可靠的「触发失败」手段。在 C++ 里，让这些操作安全是程序员自己的全部责任。

6.3 链式比较 Chained Comparisons

Python:
inside = 0 <= x <= 100   # Python 把它看成两次用 and 连接的比较

C++:
bool inside;
inside = 0 <= x && x <= 100;   // 把两个命题显式写出来
🚫 危险

0 <= x <= 100 会被解析成 (0 <= x) <= 100，C++ 会接受这个错误的表达式——这让此类错误特别危险。请显式写成 0 <= x && x <= 100。

6.4 if / else if / else

Python:
if score >= 90:
    grade = 'A'
elif score >= 80:
    grade = 'B'
else:
    grade = 'C'

C++:
if (score >= 90) {
    grade = 'A';
} else if (score >= 80) {
    grade = 'B';
} else {
    grade = 'C';
}

决策逻辑不变。C++ 用括号、花括号、分号来标注结构。

Part 7 · 循环 Loops

7.1 计数 for 循环 Counted for Loops

Python:
for i in range(n):
    print(i)

C++:
for (int i = 0; i < n; ++i) {
    std::cout << i << '\n';
}

三段分别表示：

  • int i = 0 —— 只初始化一次
  • i < n —— 每次迭代前先测试
  • ++i —— 每次迭代后更新

两个循环都遍历半开整数区间 \([0, n)\)。

7.2 while 循环 while Loops

Python:
remaining = 3
while remaining > 0:
    print(remaining)
    remaining -= 1

C++:
int remaining = 3;
while (remaining > 0) {
    std::cout << remaining << '\n';
    --remaining;
}

一个 while 循环的三要素：状态（state） remaining、继续条件 remaining > 0、进展（progress） --remaining。少了任何一个，循环就可能出错。

7.3 do–while 循环 do–while Loops

int choice = 0;
do {
    std::cout << "1. Continue\n";
    std::cout << "0. Exit\n";
    std::cin >> choice;
} while (choice != 0);

先执行循环体，再检查条件——因此菜单至少出现一次。

✏️ 备注

Java 也有 do–while；Python 通常用 while True + break 表达同样的模式。

7.4 break / continue / exit

在 i == 3 处，把注释替换成下面三种语句之一：

for (int i = 1; i <= 5; ++i) {
    if (i == 3) {
        /* 在这里放语句 */
    }
    std::cout << i << ' ';
}
std::cout << "Done\n";
语句效果输出
break;离开循环，从循环后继续1 2 Done
continue;跳过本次迭代剩余部分；for 的更新 ++i 仍会执行1 2 4 5 Done
std::exit(0);终止整个程序；0 表示成功终止1 2（没有 Done）
⚠️ 注意
  • std::exit 是一个函数，要使用它需在 main() 上方 #include <cstdlib>。
  • 在嵌套循环里，break 和 continue 只影响最内层循环。
  • 在 while 循环里，continue 可能跳过手动更新、阻止进展。

8.1 auto 类型推导 Type Deduction with auto

C++11 引入了类型推导的 auto，让声明更方便。编译器在编译期用初始值推导类型。这并不会给变量带来 Python 式的动态绑定。

声明推导类型等价声明
auto count = 5;intint count = 5;
auto rate = 2.5;doubledouble rate = 2.5;
auto ready = true;boolbool ready = true;
auto grade = 'A';charchar grade = 'A';
auto i;     // 错误：没有初始值
i = 5;      // 之后的赋值无法补救声明
auto i = 5; // OK：推导为 int
i = 6;      // 后续赋值保持同一类型

8.2 推导出的类型固定不变 The Deduced Type Stays Fixed

Python:
x = 5
x = 2.5
print(x)     // 2.5：名字现在指向浮点值

C++:
auto x = 5;
x = 2.5;
std::cout << x;   // 2：x 仍是 int，赋值丢弃小数部分
📌 要点

auto y = 5.0; y = 2; —— y 仍是 double，存 2.0。初始值一次性决定类型；值可以变，推导出的类型不变。

8.3 不会自动拓宽 No Automatic Widening

auto 只看初始值，不会预判后续计算。假设 32 位 int，最大值 2,147,483,647：

// 初始值是 int 类型
auto x = 1000000000;
x = x * 3;
std::cout << x;   // x 仍是 int，乘法超出范围 → 有符号溢出，未定义行为

// 刻意用更宽的类型
auto x = 1000000000LL;
x = x * 3;
std::cout << x;   // 3000000000：LL 让初始值成为 long long
🎯 一句话

Python 整数可以增长；C++ 整数变量保持自己的类型、存储大小和范围。auto 不会根据未来的用途选更宽的类型。

8.4 auto 跟随表达式 auto Follows the Expression

先推导表达式的类型，再初始化变量。

int total = 5;
int count = 2;

auto a = total / count;        // int    → 2
auto b = 1.0 * total / count;  // double → 2.5
auto c = a * 1.0;              // double → 2.0

整数除法之后再乘 1.0，无法找回已经丢失的小数部分。Python 里 total / count 得 2.5，total // count 得 2。auto 跟随表达式的类型，而不是你「想要的结果」。

8.5 std::pair Two Values with std::pair

std::pair 把两个值合成一个对象。< > 里的类型指定第一、第二个分量。

std::pair<double, double> roots{1.0, 2.0};
// 在 main() 内部创建带有两个 double 分量的 roots

roots.first第一个分量1.0

两个分量类型可以不同，如 std::pair<bool, double>。成员名永远是 first 和 second。当两个位置的含义很清楚时，pair 很方便。

8.6 struct 具名成员 A struct with Named Members

一个二次方程的结果要记录「是否有实根」以及「根的值」。对 \(x^2 - 3x + 2 = 0\)，实根是 1 和 2。

// 嵌套 pair 的写法（不直观）
std::pair<bool, std::pair<double, double>> result{true, {1.0, 2.0}};
// result.first           → true（是否有实根）
// result.second.first    → 1.0（第一个根）
// result.second.second   → 2.0（第二个根）

对 \(x^2 + 1 = 0\)，布尔是 false，根字段不用。这个类型能用，但 second.first 让我们得自己「解码」含义。能不能让数据带上有意义的名字？——这就是 struct 的动机。

struct QuadraticResult {
    bool hasRealRoots;
    double firstRoot;
    double secondRoot;
};
// 类型定义放在 main() 上方，别忘了最后的分号 ;

QuadraticResult result{ true, 1.0, 2.0 };
// 在 main() 内部创建对象，初始值按成员顺序排列
嵌套 pair具名 struct
result.firstresult.hasRealRoots
result.second.firstresult.firstRoot
result.second.secondresult.secondRoot
🎯 存储的信息相同，成员名解释了含义

存的信息是一样的，但成员名让含义自明。

8.7 使用与复制 struct Using and Copying a struct

用 . 读写成员，就像 first 和 second 一样。

if (result.hasRealRoots) {
    std::cout << result.firstRoot << ' ';
    std::cout << result.secondRoot << '\n';
}
// 输出：1 2（仅当 hasRealRoots 为 true 时才用根字段）

auto copy = result;
copy.firstRoot = 5.0;
// auto 推导出 QuadraticResult；这是字段的一份独立拷贝
// copy.firstRoot 变成 5.0，result.firstRoot 仍是 1.0
✏️ 什么时候用哪个

两个值有清楚的位置含义时用 pair；具名字段让数据更易理解时用 struct。

8.8 struct 的运算 Operations on a struct

内置类型（如 int）已经支持算术、比较和流 I/O；我们定义的 QuadraticResult 并不自动提供这些运算。

9.1 把数字归零 Reduce a Number to Zero · LeetCode 1342 · Easy

题目：若当前数字是偶数就除以 2，否则减 1；统计到达 0 的步数。

走一遍 num = 14：14 → 7 → 6 → 3 → 2 → 1 → 0，共 6 次状态变化，答案是 6。

int numberOfSteps(int num) {
    int steps = 0;
    while (num > 0) {
        if (num % 2 == 0) num /= 2;
        else              num -= 1;
        ++steps;           // 两个分支都要计数
    }
    return steps;
}
✏️ 程序解剖
  • 状态（state）：当前数字、步数。
  • 决策（decision）：用 num % 2 判断奇偶。
  • 循环：当前数字为正时继续。
⚠️ 容易出错
  • 两个分支都要把步数加一。
  • 输入可能本来就是 0（答案是 0）。

9.2 各位数字的积与和 Digits: Product Minus Sum · LeetCode 1281 · Easy

题目：给定正整数，返回「各位数字的积」减去「各位数字的和」。

走一遍 n = 234：digits 4, 3, 2 → sum = 9, product = 24 → 24 − 9 = 15。

int subtractProductAndSum(int n) {
    int sum = 0, product = 1;   // 乘积从 1 开始，不是 0
    while (n > 0) {
        int digit = n % 10;     // 取最后一位
        sum += digit;
        product *= digit;
        n /= 10;                // 去掉最后一位
    }
    return product - sum;
}
✏️ 程序解剖
  • 反复用 % 10 取最后一位；用 n / 10 去掉它。
  • 同时维护累加和（running sum）与累乘积（running product）。
⚠️ 容易出错
  • 乘积必须从 1 开始，而不是 0（否则永远是 0）。
  • 每次迭代都必须去掉一位（否则死循环）。

9.3 迭代斐波那契 Iterative Fibonacci · LeetCode 509 · Easy

题目：计算 \(F(n)\)，其中 \(F(0)=0, F(1)=1\)，之后每一项是前两项之和。

int fib(int n) {
    if (n == 0) return 0;          // 显式处理 n = 0
    int previous = 0, current = 1;
    for (int i = 1; i < n; ++i) {
        int next = previous + current;  // 先用临时值算出 next
        previous = current;
        current = next;
    }
    return current;
}
✏️ 程序解剖
  • 显式处理 n = 0。
  • 只保留最近两个值（previous 和 current），滚动前进。
  • 在替换任何一个旧值之前先算好下一个值。
⚠️ 容易出错

Python 允许 a, b = b, a + b 一次交换；C++ 里要用临时变量保存旧状态，避免顺序错误。

9.4 回文数 Palindrome Number · LeetCode 9 · Easy

题目：判断一个整数是否正读反读相同，不要转成字符串。

bool isPalindrome(int x) {
    if (x < 0) return false;        // 拒绝负数
    long long remaining = x, reversed = 0;
    while (remaining > 0) {
        reversed = reversed * 10 + remaining % 10;  // 取一位，拼到反转值
        remaining /= 10;
    }
    return x == reversed;           // 保留原值做最终比较
}

走一遍 121：remaining 121 → 12 → 1 → 0；reversed 0 → 1 → 12 → 121；121 == 121。

⚠️ 容易出错
  • 10 不是回文数：反转会丢掉前导零（10 → 1）。
  • 反转值用 long long，防止反转过程中溢出。

9.5 坏了的计算器 Broken Calculator · LeetCode 991 · Medium

题目：从 start 出发，用最少的操作到达 target。只有两种操作：翻倍 \(x = x \times 2\)，或减一 \(x = x - 1\)。约束 \(1 \le start, target \le 10^9\)。

例子 start = 3, target = 10：

  • 先翻倍直到超过再减：3 → 6 → 12 → 11 → 10（4 步）。
  • 翻倍前先减：3 → 6 → 5 → 10（3 步）——更短。
📌 关键观察

「只要小于 target 就一直翻倍」可能错过更短路径。换成从 target 往回走，问题变得简单：逆操作是「加 1」或「把偶数除以 2」。

当前 target逆操作原因
奇数target += 1加 1 是唯一合法动作
偶数target /= 2先减半更省步数
✏️ 为什么偶数要先减半？

加两次再减半：10 → 11 → 12 → 6（3 步）；先减半再加：10 → 5 → 6（2 步）。减半前的每两次加法，都能变成减半后的一次加法。

int brokenCalc(int start, int target) {
    int ops = 0;
    while (target > start) {
        if (target % 2 == 1) target += 1;   // 奇数只能加 1
        else                 target /= 2;   // 偶数先减半
        ++ops;
    }
    return ops + (start - target);   // 剩余差距只需一路减一
}
✏️ 边界检查
  • start == target 得 0。
  • start = 10, target = 3：答案是 7（一路减一）。
