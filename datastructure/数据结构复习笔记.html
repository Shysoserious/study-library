Part 1 · 区间和查询 Range Sum Querying Oracle

1.1 问题描述

✏️ 问题

输入（Input）： \(n\) 个元素 \(a_1, a_2, \dots, a_n\)

请求（Request）： 提供一个 API calc(l, r)，返回

\(a_l + a_{l+1} + \cdots + a_r\)

即「第 \(l\) 个到第 \(r\) 个元素的区间和（range sum）」。

这个例子贯穿整讲：同样一个问题，用不同的数据结构去存数据，查询和预处理的成本完全不同。下面依次看三种方案。

1.2 朴素解法一：循环求和 Naive Solution

把元素存进数组 \(A[\ ]\)（\(a_i\) 就是 \(A[i]\)）。每次调用 API 时，用一个循环把区间里的元素加起来。

ALGORITHM calc(l, r)
  total ← 0
  FOR i ← l TO r DO
    total ← total + A[i]
  RETURN total
衡量指标朴素解法一
每次查询的加法次数最坏情况多达 \(n\) 次
存储一个大小为 \(n\) 的数组

1.3 朴素解法二：预计算所有区间 Naive Solution 2

注意到不同的区间一共有 \(n(n+1)/2\) 个（任选起点 \(l\) 和终点 \(r\ge l\)）。干脆提前把每个区间和都算好，存进表 \(ANS[l, r]\)。查询时直接查表。

ALGORITHM calc(l, r)
  RETURN ANS[l, r]
衡量指标朴素解法二
每次查询的加法次数0 次（直接查表）
存储一个 \(n \times n\) 的表
⚠️ 用空间换时间

解法二查询极快，但存储是 \(O(n^2)\) 级别——「时间（time）」和「空间（space）」之间出现了权衡。这正是数据结构要面对的核心矛盾。

1.4 前缀和数据结构 Prefix Data Structure

能不能既查询快、又省存储？答案是前缀和（prefix sum）：把「前 \(i\) 个元素的和」存在 \(PRE[i]\) 里。

📌 前缀和的定义

\(PRE[i] = a_1 + a_2 + \cdots + a_i \qquad (PRE[0] = 0)\)

查询时返回：

\(\mathrm{calc}(l, r) = PRE[r] - PRE[l-1]\)

为什么成立？

把 \(PRE[r]\) 拆成两段：

\(PRE[r] = \underbrace{a_1 + \cdots + a_{l-1}}_{=\,PRE[l-1]} + \underbrace{a_l + \cdots + a_r}_{\text{想求的区间和}}\)

于是 \(PRE[r] - PRE[l-1] = a_l + \cdots + a_r\)，正好是区间和。

ALGORITHM calc(l, r)
  RETURN PRE[r] − PRE[l−1]
衡量指标前缀和
每次查询的算术运算1 次减法
存储一个含 \(n+1\) 项的数组（含 \(PRE[0]\)）

1.5 隐藏成本：预处理 Hidden Cost: Preprocessing

只看「每次查询」是不够的——三种方案建数据结构（预处理）的成本完全不同。把隐藏成本摊开看：

方案预处理伪代码加法次数
朴素解法一 FOR i ← 1 TO n DO A[i] ← a_i 0 次（\(n\) 次赋值）
朴素解法二（直接构造） 三层循环：对每个 \(l, r\)，再循环 \(i\) 累加 \(n(n+1)(n+2)/6\) 次
朴素解法二（复用前一个答案） ANS[l, r] ← ANS[l, r−1] + A[r] \(n(n+1)/2\) 次
前缀和 PRE[i] ← PRE[i−1] + A[i] \(n\) 次 
前缀和预处理：
PRE[0] ← 0
FOR i ← 1 TO n DO
  PRE[i] ← PRE[i−1] + A[i]
🎯 结论

前缀和完胜：预处理只需 \(n\) 次加法、存储是线性的 \(O(n)\)，却能支持 \(O(1)\) 的查询。它用「一次预处理」换来「之后每次查询都极快」。

为什么解法二「复用前一个答案」比「直接构造」好？因为 \(ANS[l,r] = ANS[l,r-1] + A[r]\) 复用了刚算出的 \(ANS[l,r-1]\)，把最内层循环省掉了——避免重复计算是算法设计最常用的技巧之一。

1.6 更进一步：更新与更多查询 We Always Ask for More

前缀和虽好，但需求一变，它就可能不够用了。老师抛出两个「进阶需求」：

✏️ 需求升级
  • 数据会变（evolving data）：还要支持 update(i, x)，即 \(a_i \leftarrow x\)（改掉某一个元素）。前缀和一旦改一个元素，所有 \(PRE[i], PRE[i+1], \dots\) 都要跟着改。
  • 更复杂的查询（complicated queries）：比如改问区间乘积 \(a_l \times a_{l+1} \times \cdots \times a_r\)——前缀「和」就没法直接套用了。

⇝ 老师留了个悬念：后续课程会学到能处理这些问题的数据结构（如树状数组、线段树、平衡树等）。这正是这门课要展开的方向。

Part 2 · 从 Python/Java 到 C++ From Java/Python to C++

2.1 同一个算法，不同的职责划分

看一个最简单的任务：输入整数 \(n\)，输出 \(2n\)。算法几乎不变，变的是「程序员、编译器、运行时」三者的职责分工。

Python:
n = int(input())
print(2 * n)

Java:
import java.util.Scanner;
class Main {
  public static void main(String[] args) {
    Scanner input = new Scanner(System.in);
    int n = input.nextInt();
    System.out.println(2 * n);
  }
}

C++:
#include <iostream>
int main() {
  int n;
  std::cin >> n;
  std::cout << 2 * n << '\n';
  return 0;
}
✏️ 关键点

你早就知道怎么写这个程序；现在要学的是「如何把同一个意思表达给 C++ 编译器」。三种语言把这个简单任务背后的职责（类型检查、内存管理、执行时机）放在了不同的位置。

2.2 为什么学完 Python/Java 还要学 C++

Python、Java、C++ 在「责任（responsibility）」和「控制（control）」上做了不同的默认选择（default choices）。

以「往列表里加一个元素」为例：

Python:  a = []        ; a.append(x)
Java:    ArrayList<Integer> a = new ArrayList<>();  a.add(x);

C++ 会逼你追问这些被高层语言「藏起来」的问题：

  • 这个 API 隐藏（hide）了什么？
  • 元素在内存里是怎么排布（arranged in memory）的？
  • 可用空间用完时会发生什么？
  • 为什么在末尾插入通常很快，在开头插入通常很慢？
  • 扩容时要不要复制已有元素？
🎯 一句话

Python/Java 帮你做了很多决定；C++ 让你看清并自己决定这些细节——这正是学数据结构需要的视角。

2.3 C++ 与数据结构：抽象 ↔ 表示 ↔ 成本

📌 数据结构课问的三件事
  1. 这个 API 做什么？（abstract operation 抽象操作——程序应该完成什么）
  2. 数据怎么存？（concrete representation 具体表示——数据在内存里如何布局）
  3. 这个选择花多少代价？（time and space cost 时间与空间成本——需要多少运算和内存）

抽象操作（what the program should do）\(\longleftrightarrow\) 具体表示（how data is stored）\(\longleftrightarrow\) 时间与空间成本（what work and memory are required）

🎯 为什么是 C++

C++ 让我们把「操作」「表示」「实际成本」三者连起来看。高层语言（如 Python）把表示和成本都藏起来了，你很难体会到「换个数据结构」到底省了什么。

Part 3 · 语言观念的转变 Shifting Mindsets

3.1 高级语言 ≠ 面向对象 High-Level and Object-Oriented Are Different

概念含义例子
高级语言
high-level language		 用变量、循环、函数、容器来表达，而不必直接写机器指令 total += x 一句可能对应底层多次 load、add、store 操作
面向对象编程
object-oriented programming		 通过「对象」把相关的状态（state）和行为（behavior）组织起来，常用类（class）来描述 account.deposit(x) 让拥有余额的对象自己更新状态

三种语言的定位：

  • Python：面向对象是可选的、动态的；代码可以写在类外，名字通常指向对象。
  • Java：应用代码以类为中心；对象变量通常持有由 JVM 管理的引用。
  • C++：多范式（multi-paradigm）；代码可以写在类外，对象可以直接作为值存在，也可以间接访问。
✏️ 具体后果

一个独立的辅助函数在 Python 和 C++ 里很自然；Java 通常把它放进某个类里作为方法。高层抽象仍有真实的时间和内存成本；面向对象 ≠ 所有东西都得是类。

3.2 更多控制 = 更多责任 More Control Means More Responsibility

语言默认行为
Python通常隐藏静态类型、对象布局、内存管理的细节
Java让大多数类型显式，但 JVM 仍替你管理对象和内存
C++要求你理解对象如何被存储、复制、移动、销毁

一个「预览（preview）」，现在不要求背：

int x = 10;

  • sizeof(x) —— 检查对象的大小
  • &x —— 观察对象的存储位置
  • a.reserve(1000) —— 控制容器的计划容量
🎯 三种语言一句话总结
  • Python —— 方便地表达想法（Express ideas conveniently）
  • Java —— 在受管运行时里安全地组织对象（Organize objects safely inside a managed runtime）
  • C++ —— 保留高层抽象的同时，控制表示和成本（Keep high-level abstractions while controlling representation and cost）

在 C++ 里，我们同时看到抽象、表示、操作成本和内存行为。

语言执行路径特点
Python 源码 → 由 Python 运行时执行 更多行为在程序运行时由运行时决定
Java 源码 → Java 字节码 → JVM 执行或即时编译（JIT） 字节码面向受管虚拟机，虚拟机可在执行中优化

Part 3 · 变量与初始化 Variables & Initialization

3.1 声明、初始化、赋值 Declaration / Initialization / Assignment

概念代码含义
声明（declaration）int total;创建一个没有初始值的局部变量
初始化（initialization）int total = 0;创建一个带起始值的变量
赋值（assignment）total = 5; total = total + 2;更新已存在的变量；最终值是 7

我们通常用 =。此外 int x(5); 和 int x{5}; 也都能把 x 初始化成 5。

3.2 窄化转换：小括号 / = / 花括号 Narrowing Conversions

如果初始值是 5.5（而不是 5）会怎样？三种写法结果不同：

独立示例结果原因
int x(5.5);编译通过：x = 5丢弃小数部分
int x = 5.5;编译通过：x = 5发生同样的转换
int x{5.5};编译期错误花括号拒绝窄化转换（narrowing conversion）
⚠️ 注意

小括号和 = 允许截断（truncate），而不是四舍五入到最近的整数；编译器可能给出警告。

要零初始化，int total{0}; 和 int total{}; 都能从 0 开始。

3.3 未初始化的局部变量 Uninitialized Local Variables

int count;           // 不要读这个值
std::cout << count;

没有发生初始化。在 C++20 中读取这个局部 int 是未定义行为（undefined behavior）。

int count;           // 先赋值，再读
count = 0;
std::cout << count;  // 打印 0
🚫 铁律

永远不要假设未初始化的局部变量是 0！

程序可能看起来打印 0、打印别的值，或者在不同运行、不同编译器、不同编译设置、不同环境下表现各异——这些观察都不构成任何保证。

（全局变量和静态变量遵循不同的初始化规则；这条警告针对的是普通的局部变量。）

4.3 前缀与后缀自增 Prefix and Postfix Increment

两种形式都让 x 增加 1，但它们的表达式提供不同的值：

前缀：用新值
int x = 5;
int y;
y = ++x;    // x = 6, y = 6

后缀：用旧值
int x = 5;
int y;
y = x++;    // x = 6, y = 5
int x = 5;
std::cout << x++ << '\n';   // 打印 5，然后 x 变成 6
std::cout << ++x << '\n';   // 先增到 7，再打印
std::cout << x << '\n';     // 打印当前的 x
// 输出：5  7  7
✏️ 备注
  • 作为独立语句，++x; 和 x++; 对 int 效果相同。同样的区别适用于 --x 和 x--。
  • Java 有同样的区别；Python 没有自增运算符，用 x += 1。

4.4 预测值练习 Predict the Values

每个例子独立开始，问最后一条语句之后的值是多少：

int x = 3; int y;
y = x++ * 2;      // x = 4, y = 6

int x = 3; int y;
y = ++x * 2;      // x = 4, y = 8

int x = 3; int y;
y = x++;
y += ++x;         // x = 5, y = 8

int x = 3; int y;
y = x-- + 10;     // x = 2, y = 13
🚫 通用建议

让更新易于理解：用分开的语句，不要把对同一变量的多次修改塞进一个表达式。不确定某段代码会怎么表现，就不要写它。

Part 5 · 溢出与类型陷阱 Overflow & Type Pitfalls

5.1 有符号整数溢出 Signed Integer Overflow

假设是 32 位 int：其最大值是 2,147,483,647。

int x;
std::cin >> x;   // 输入 2147483647
x = x + 1;
std::cout << x;

数学结果是 2,147,483,648，但这个结果无法用 int 表示。在 C++ 里，有符号整数溢出是未定义行为（undefined behavior）。

语言 / 类型给 2,147,483,647 加 1
Python int2147483648 —— 整数可以增长
Java int−2147483648 —— 定义好的 32 位回绕
C++ 32 位 int没有保证的结果——甚至不保证崩溃
✏️ 为什么程序可能继续运行？

普通机器指令可能只保留低 32 位，未必抛出异常：

01111111 11111111 11111111 11111111   （2,147,483,647）
+ 1
10000000 00000000 00000000 00000000   （若按有符号 32 位解释为 −2,147,483,648）

这只解释了一种常见的观察结果，是硬件层面的示意，不是 C++ 对有符号溢出的有效规则。编译器可能假设有符号溢出永不发生来优化；换个编译设置可能得到不同结果——甚至没有有用的结果。在支持的编译器上，-fsanitize=undefined 能在运行时报告有符号溢出。

5.2 无符号回绕 Unsigned Arithmetic Wraps Around

与有符号溢出不同，无符号算术定义为模 \(2^w\)。对 32 位 unsigned int，模是 4,294,967,296。

// 超过最大值
unsigned int x = 4294967295U;
x = x + 1;
std::cout << x;   // 0

// 低于零
unsigned int x = 0;
x = x - 1;
std::cout << x;   // 4294967295
⚠️ 有符号 / 无符号混用很危险

无符号只是有更大的非负范围，不是算术错误的保护伞。

int a = -1;
unsigned int b = 1;
std::cout << (a < b);   // 0：false！

这里 a 在比较前被转换成 unsigned int。按 32 位示例，−1 变成 4,294,967,295。避免随意混用有符号和无符号。

5.3 先拓宽再运算 Widen Before the Operation

目标类型无法修复「计算它的表达式」里已经发生的溢出。

// 太迟了
int a = 100000;
long long square;
square = a * a;      // a * a 按 int 计算；10,000,000,000 放不下

// 用一个更宽的操作数
int a = 100000;
long long square;
square = 1LL * a * a;   // 1LL 是 long long，两次乘法都用更宽的类型

long long wide;
wide = a;
square = wide * a;      // 也是 10000000000
⚠️ 仍然要检查范围

即使 long long 也是有限的。先让一个操作数变宽，再运算。

5.4 布尔与字符算术 Boolean and Character Arithmetic

bool 和字符值可以参与整数算术。小的整数类型通常在运算前被提升（promote）为 int。

Part 6 · 布尔表达式与控制流 Boolean Expressions & Control Flow

6.1 短路求值 Short-Circuit Evaluation

关系与逻辑运算符：== != < <= > >= && || !

短路求值：先算左边，一旦结果已确定就停止。

// 逻辑与 &&
int d = 0;
bool result;
result = (d != 0 && 10 / d > 2);
// 左边是 false → 跳过右边，结果是 false
// 10 / d 根本不会执行，所以没有除以零

// 逻辑或 ||
int d = 0;
bool result;
result = (d == 0 || 10 / d > 2);
// 左边是 true → 跳过右边，结果是 true
// 10 / d 在这里也不会执行
✏️ 关键点

被跳过的表达式完全不执行——即使跳过的那一侧有 ++x，x 也不会被改变。

6.2 短路与程序员的责任 Short-Circuiting and Responsibility

这个数组有三个元素，合法下标是 0、1、2。

// &&：跳过不安全的数组访问
int a[3] = {10, 20, 30};
int i = 5;
bool found = ((0 <= i && i < 3) && a[i] == 20);
// i = 5：边界检查失败，所以 a[i] 被跳过
// i = 0：读到 10，found 为 false；i = 1：读到 20，为 true

// ||：故意触发失败
bool fail();   // 提供的辅助函数：报告错误并退出
bool valid = (0 <= i && i < 3);
valid || fail();
// i = 5：valid 为 false，fail() 运行并终止程序
// i = 1：valid 为 true，fail() 被跳过
⚠️ 责任边界

越界读取是未定义行为，不是可靠的「触发失败」手段。在 C++ 里，让这些操作安全是程序员自己的全部责任。

6.3 链式比较 Chained Comparisons

Python:

C++:

inside = 0 <= x && x <= 100;   // 把两个命题显式写出来
🚫 危险

0 <= x <= 100 会被解析成 (0 <= x) <= 100，C++ 会接受这个错误的表达式——这让此类错误特别危险。请显式写成 0 <= x && x <= 100。

7.1 计数 for 循环 Counted for Loops

C++:

}

三段分别表示：

  • i < n —— 每次迭代前先测试
  • ++i —— 每次迭代后更新

两个循环都遍历半开整数区间 \([0, n)\)。

7.2 while 循环 while Loops

Python:
remaining = 3

    print(remaining)
    remaining -= 1

C++:
int remaining = 3;

    std::cout << remaining << '\n';
    --remaining;
}

一个 while 循环的三要素：状态（state） remaining、继续条件 remaining > 0、进展（progress） --remaining。少了任何一个，循环就可能出错。

7.3 do–while 循环 do–while Loops

do {
    std::cout << "1. Continue\n";
    std::cout << "0. Exit\n";

} while (choice != 0);

先执行循环体，再检查条件——因此菜单至少出现一次。

✏️ 备注

7.4 break / continue / exit

8.3 不会自动拓宽 No Automatic Widening

auto 只看初始值，不会预判后续计算。假设 32 位 int，最大值 2,147,483,647：

auto x = 1000000000;
x = x * 3;

// 刻意用更宽的类型

🎯 一句话

Python 整数可以增长；C++ 整数变量保持自己的类型、存储大小和范围。auto 不会根据未来的用途选更宽的类型。

8.4 auto 跟随表达式 auto Follows the Expression

先推导表达式的类型，再初始化变量。

int total = 5;

auto a = total / count;        // int    → 2
auto b = 1.0 * total / count;  // double → 2.5
auto c = a * 1.0;              // double → 2.0

整数除法之后再乘 1.0，无法找回已经丢失的小数部分。Python 里 total / count 得 2.5，total // count 得 2。auto 跟随表达式的类型，而不是你「想要的结果」。

9.1 把数字归零 Reduce a Number to Zero · LeetCode 1342 · Easy

题目：若当前数字是偶数就除以 2，否则减 1；统计到达 0 的步数。

走一遍 num = 14：14 → 7 → 6 → 3 → 2 → 1 → 0，共 6 次状态变化，答案是 6。

int numberOfSteps(int num) {
    int steps = 0;
    while (num > 0) {
        if (num % 2 == 0) num /= 2;
        else              num -= 1;
        ++steps;           // 两个分支都要计数
    }
    return steps;
}
✏️ 程序解剖
  • 状态（state）：当前数字、步数。
  • 决策（decision）：用 num % 2 判断奇偶。
  • 循环：当前数字为正时继续。
⚠️ 容易出错
  • 两个分支都要把步数加一。
  • 输入可能本来就是 0（答案是 0）。

9.2 各位数字的积与和 Digits: Product Minus Sum · LeetCode 1281 · Easy

题目：给定正整数，返回「各位数字的积」减去「各位数字的和」。

走一遍 n = 234：digits 4, 3, 2 → sum = 9, product = 24 → 24 − 9 = 15。

int subtractProductAndSum(int n) {
    int sum = 0, product = 1;   // 乘积从 1 开始，不是 0
    while (n > 0) {
        int digit = n % 10;     // 取最后一位
        sum += digit;
        product *= digit;
        n /= 10;                // 去掉最后一位
    }
    return product - sum;
}
✏️ 程序解剖
  • 反复用 % 10 取最后一位；用 n / 10 去掉它。
  • 同时维护累加和（running sum）与累乘积（running product）。
⚠️ 容易出错
  • 乘积必须从 1 开始，而不是 0（否则永远是 0）。
  • 每次迭代都必须去掉一位（否则死循环）。

9.3 迭代斐波那契 Iterative Fibonacci · LeetCode 509 · Easy

题目：计算 \(F(n)\)，其中 \(F(0)=0, F(1)=1\)，之后每一项是前两项之和。

int fib(int n) {
    if (n == 0) return 0;          // 显式处理 n = 0
    int previous = 0, current = 1;
    for (int i = 1; i < n; ++i) {
        int next = previous + current;  // 先用临时值算出 next
        previous = current;
        current = next;
    }
    return current;
}
✏️ 程序解剖
  • 显式处理 n = 0。
  • 只保留最近两个值（previous 和 current），滚动前进。
  • 在替换任何一个旧值之前先算好下一个值。
⚠️ 容易出错

Python 允许 a, b = b, a + b 一次交换；C++ 里要用临时变量保存旧状态，避免顺序错误。

9.4 回文数 Palindrome Number · LeetCode 9 · Easy

题目：判断一个整数是否正读反读相同，不要转成字符串。

bool isPalindrome(int x) {
    if (x < 0) return false;        // 拒绝负数
    long long remaining = x, reversed = 0;
    while (remaining > 0) {
        reversed = reversed * 10 + remaining % 10;  // 取一位，拼到反转值
        remaining /= 10;
    }
    return x == reversed;           // 保留原值做最终比较
}

走一遍 121：remaining 121 → 12 → 1 → 0；reversed 0 → 1 → 12 → 121；121 == 121。

⚠️ 容易出错
  • 10 不是回文数：反转会丢掉前导零（10 → 1）。
  • 反转值用 long long，防止反转过程中溢出。

9.5 坏了的计算器 Broken Calculator · LeetCode 991 · Medium

题目：从 start 出发，用最少的操作到达 target。只有两种操作：翻倍 \(x = x \times 2\)，或减一 \(x = x - 1\)。约束 \(1 \le start, target \le 10^9\)。

例子 start = 3, target = 10：

  • 先翻倍直到超过再减：3 → 6 → 12 → 11 → 10（4 步）。
  • 翻倍前先减：3 → 6 → 5 → 10（3 步）——更短。
📌 关键观察

「只要小于 target 就一直翻倍」可能错过更短路径。换成从 target 往回走，问题变得简单：逆操作是「加 1」或「把偶数除以 2」。

当前 target逆操作原因
奇数target += 1加 1 是唯一合法动作
偶数target /= 2先减半更省步数
✏️ 为什么偶数要先减半？

加两次再减半：10 → 11 → 12 → 6（3 步）；先减半再加：10 → 5 → 6（2 步）。减半前的每两次加法，都能变成减半后的一次加法。

int brokenCalc(int start, int target) {
    int ops = 0;
    while (target > start) {
        if (target % 2 == 1) target += 1;   // 奇数只能加 1
        else                 target /= 2;   // 偶数先减半
        ++ops;
    }
    return ops + (start - target);   // 剩余差距只需一路减一
}
✏️ 边界检查
  • start == target 得 0。
  • start = 10, target = 3：答案是 7（一路减一）。

2.8 边读边处理 Read While Reading Succeeds

int x;

Part 3 · C 风格 I/O scanf and printf

3.1 scanf / printf Basic Usage

C 用 <stdio.h> 提供 scanf 和 printf。在 C++ 里，包含 <cstdio> 后使用。

int n;
double price;
if (scanf("%d %lf", &n, &price) == 2) {
    printf("n=%d, price=%.2f\n", n, price);
}
// 输入 3 12.5 输出：n=3, price=12.50
  • 输入格式：%d 读一个 int；%lf 读一个 double。&n、&price 指定值存到哪。
  • 返回值：scanf 返回「成功赋值的个数」，用 == 2 检查两个值都成功读入。
  • 输出格式：%.2f 表示本次调用打印两位小数。格式串描述要做哪些转换。
✏️ 关于 &

这里的 & 是「取地址」，我们会在第 5 课正式解释地址（address）和 &。现在先记住：scanf 需要 &变量 告诉它把值写到哪里。

3.2 格式串与类型对照 Format Strings and Types

对每一行，x 的类型如表所示；格式必须与实际传入的参数类型匹配。

x 的类型用 scanf 读用 printf 写
intscanf("%d", &x);printf("%d", x);
long longscanf("%lld", &x);printf("%lld", x);
floatscanf("%f", &x);printf("%f", x);
doublescanf("%lf", &x);printf("%f", x);
⚠️ 两个容易踩的坑
  • float 与 double 在读入时格式不同（%f vs %lf）：printf 收到 float 会被提升为 double，但 scanf 必须区分两种目标类型。
  • 格式与参数不匹配会导致未定义行为（undefined behavior）——编译器警告能帮上忙，但格式串本身不是类型安全的接口。
  • 对于 char ch，用 scanf(" %c", &ch)（前面有个空格）来跳过空白；单独用 "%c" 会读下一个字符，哪怕是换行符。

两者都可以很高效，性能取决于具体负载、缓冲（buffering）、同步（synchronization）和实现。本课的示例统一用 cin/cout，但两种接口都要认识。

4.9 LeetCode 434 字符串中的单词数 Number of Segments in a String

📝 题目（LeetCode 434 · Easy）

统计字符串里由空格分隔的非空字符组（segment）的个数。标点符号和字母一样属于某个组。

输入 s单词数
" learn C++ together! "3
"hello,world"1
"" 或 " "0

提取出的词："learn"、"C++"、"together!"。

#include <sstream>
int countSegments(string s) {
    istringstream in(s);   // 从 s 建一个 istringstream
    string word;
    int cnt = 0;
    while (in >> word) {  // 一次读一个 string（词）
        ++cnt;             // 只有提取成功才计数
    }
    return cnt;
}
⚠️ 容易写错的地方
  • 数空格在空格连续出现时会数错——用「成功读一个词就 +1」更稳。
  • 逗号不会结束一个组（"hello,world" 是一个组）。
  • 从 0 开始计数，天然处理空输入。
  • 只需保留「当前词 + 计数」，不需要存下所有词。

4.14 LeetCode 1768 交替合并字符串 Merge Strings Alternately

📝 题目（LeetCode 1768 · Easy）

交替取两个字符串的字符，从 word1 开始；当一个字符串结束，把另一个剩余字符全部接上。

word1 = "cat"，word2 = "dogs"：

位置来自 word1来自 word2结果
0cd"cd"
1ao"cdao"
2tg"cdaotg"
3无字符s"cdaotgs"
string mergeAlternately(string w1, string w2) {
    string res;               // 位置 i + 初始为空的结果
    int i = 0;
    while (i < w1.size() || i < w2.size()) {  // 任一还有字符就继续
        if (i < w1.size()) res += w1[i];      // 各自单独检查边界
        if (i < w2.size()) res += w2[i];
        ++i;
    }
    return res;
}

5.1 为什么要 vector Store a Sequence with vector

int scores[3]; 只有三个值的空间；当更多值到来时，这个定长数组无法增长。

Python:
scores = []
scores.append(85)

Java:
ArrayList<Integer> scores = new ArrayList<>();
scores.add(85);

C++:
vector<int> scores;

📌 要点

需要 #include <vector>。int 指定元素类型；元素个数可以增长。一个 vector 可以添加元素并替我们管理额外的存储。

5.2 创建 vector Creating a vector

合法下标满足 0 ≤ i < v.size()。

[] 不会让 vector 变大——要用 push_back 或 resize。Python 的列表索引和 Java 的 ArrayList.get 会检查边界；Python 的负数索引惯例不适用于 C++ 的 vector。异常（exception）之后会专门学。

5.5 size 与 capacity Size Is Not Capacity

size（大小）：实际存在多少个元素。capacity（容量）：在不需要再次分配存储的情况下能装多少个。

语句（按顺序）size元素

预留出来的空间不是「可访问的元素集合」。不先 reserve 也能 push_back；reserve 只是关于空间的可选提示，不是增长的硬性前提；具体的增长倍率不由语言规定。

5.6 两种遍历循环 Loop over the Elements

给定 vector<int> v{4, 7, 2};：

    cout << i << ": " << v[i] << '\n';

// 只需要「每个值」时（基于范围的 for）

}

5.7 循环变量是副本 A Loop Variable Can Be a Copy

// 局部值（copy）

    x *= 2;          // v 仍是 1, 2, 3
}

// 存着的值
vector<int> v{1, 2, 3};

}
📌 要点

C++:

Part 6 · vector 内部与扩容 Inside a vector

6.1 连续内存 + size/capacity Contiguous Memory

vector<int> 把元素一个挨一个放在一块连续（contiguous）的内存里。

存的值 10 20 30：size = 3（三个已存在元素），capacity = 8（再分配前能装 8 个）。

执行 push_back(40) 后：10 20 30 40，size = 4，capacity = 8——直接占用下一个空槽。

⚠️ 关键点

空槽是「预留的存储」，不是「元素」——现在还不能用 v[i] 访问它们。

6.2 存储满了怎么办 When the Storage Is Full

下面用倍增模型（doubling model）说明：块满时，分配一块两倍容量的新块。

追加 50 之前：size = 4; capacity = 4（已满）。追加后：size = 5; capacity = 8。过程：分配 → 搬移 4 个旧值 → 追加 50 → 释放旧存储。

📌 要点

这些工作由 vector 替我们完成。具体的增长倍率取决于库实现，语言标准并不规定一定是翻倍。

6.3 为什么按倍增扩容 Why Grow by Doubling?

从容量 1 开始，依次追加 8 个值，看要搬移多少次旧值：

增长策略用到的容量重新分配次数搬移的值总数
每次多一个槽（one extra slot）1,2,3,4,5,6,7,871+2+3+4+5+6+7 = 28
容量翻倍（double the capacity）1,2,4,831+2+4 = 7
✏️ 直觉

富余的容量让后面很多次追加都复用同一块内存。每次只多一个槽会反复搬移同样的早期值；翻倍则让「搬移」摊到越来越多的「直接追加」上。

6.4 扩容次数 = log₂n Counting the Expansions

从容量 1 开始，逐个追加，满了就翻倍：

sizecapacity已存的值扩容次数
1110
221 21
341 2 32
581 2 3 4 53
9161 … 94
16161 … 164

值 10–16 都装进同一块，不再扩容。16 个值：4 次扩容 = \(\log_2 16\)。对 \(n = 2^k\) 个值：\(k = \log_2 n\) 次扩容。跨 \(n\) 次插入，总共搬移的元素不到 \(2n\) 个——平均每次插入不到 2 个元素搬移（摊还分析 amortized）。

6.5 reserve 提前规划 Planning Storage with reserve

vector<int> values;
values.reserve(8);
for (int i = 0; i < 8; ++i) {
    values.push_back(i * 10);
}

执行 reserve(8) 后：size = 0，capacity ≥ 8。循环结束后：size = 8，这 8 次追加没有发生重新分配。

📌 要点

reserve 准备存储；resize 改变元素个数。给空 vector 预留空间，并不会让 values[0] 变得合法。通过接口使用 vector——同时理解它背后的工作。

6.6 读契约而不是读名字 Read the Contract, Not Just the Name

你不需要背下每个库函数，但需要检查一个操作「要求什么、保证什么」。以 v.pop_back(); 为例：

项说明

参考示例：cplusplus.com 上的 vector::pop_back。AI 的解释有用，但仍要核对操作契约并自己测试假设。

7.1 LeetCode 66 加一 Plus One

📝 题目（LeetCode 66 · Easy）

一个 vector 存一个非负整数的十进制各位，最高位在前。加一后返回新的各位。

[4, 2, 9] → [4, 3, 0]：处理个位 9 → 0，进位 1；处理十位 2 → 3，不进位，前面的 4 保持不变。

[9, 9] → [1, 0, 0]：出现新的最高位。输入可能有 100 位，把它转成 int 或 long long 是不安全的。

vector<int> plusOne(vector<int>& digits) {
    int carry = 1;                 // 从进位 1 开始，从右往左处理
    int n = digits.size();
    for (int i = n - 1; i >= 0; --i) {
        int sum = digits[i] + carry;
        digits[i] = sum % 10;      // 9 → 0 并传递进位；否则自增并结束
        carry = sum / 10;
        if (carry == 0) return digits;
    }
    digits.insert(digits.begin(), carry);  // 全 9 时多出一位最高位 1
    return digits;
}
⚠️ 容易写错的地方
  • 把长度存进 int n，从 int i = n - 1 开始。
  • 循环条件 i >= 0；下标 n 已经越界。
  • 全 9 的情况需要多一个元素（如 [9,9] → [1,0,0]）。
  • 全 9 进位后，旧位全是 0；在最前面插入 1 即可。

7.2 LeetCode 415 字符串相加 Add Strings

📝 题目（LeetCode 415 · Easy）

给定两个以字符串存储的非负整数，返回它们的和（也是字符串）。每个输入最多 10,000 位；不能把整个输入转成整数，也不许用大整数库。

num1num2结果
"456""77""533"
"999""1""1000"
"0""0""0"

数据流：string（读输入各位）→ vector<int>（存计算出的各位）→ string（拼出输出文本）。

逐位相加：从右往左，缺位当 0；字符转数字用 '6' - '0' 得到 6。

位（Place）和（Sum）该位数字进位
个位6 + 7 + 0 = 1331
十位5 + 7 + 1 = 1331
百位4 + 0 + 1 = 550
digits.push_back(sum % 10);
carry = sum / 10;
// 即便输入有 10,000 位，每一次的局部和最多 9 + 9 + 1 = 19
string addStrings(string a, string b) {
    int i = a.size() - 1, j = b.size() - 1;  // 两个下标停在最后字符
    int carry = 0;
    vector<int> digits;                       // 低位在前
    while (i >= 0 || j >= 0 || carry) {       // 任一还有位，或还有进位
        int sum = carry;
        if (i >= 0) sum += a[i] - '0';        // 各自检查边界
        if (j >= 0) sum += b[j] - '0';
        digits.push_back(sum % 10);           // 追加一位结果
        carry = sum / 10;
        --i; --j;                             // 往左移动
    }
    string res;
    for (int k = digits.size() - 1; k >= 0; --k)
        res += char('0' + digits[k]);         // 从后往前，拼出文本
    return res;
}
⚠️ 容易写错的地方
  • 访问每个字符串前先检查下标（两个串长度可能不同）。
  • 用 || 而不是 &&，否则较长的输入会被丢掉。
  • 别忘了最后的进位："999" + "1" → "1000"。
  • '0' 是字符，不是整数 0——两个方向都要转换（c - '0' 转数字，'0' + d 转字符）。
  • 测试：零、不等长、无进位、连续进位。

前三讲已经会写「一段线性执行的代码」，但真实程序要拆成可复用的函数（function）。本讲先讲函数的声明、参数、返回值、重载与默认参数；接着引入 C++ 最重要的语法之一——引用（reference），理解「传值 vs 传引用」；最后讲迭代器（iterator），它是标准库算法与容器之间的桥梁，是 C++ 泛型编程的核心。三个主题层层递进：函数 → 引用 → 迭代器。

Part 1 · 函数基础 Functions

1.1 函数接口 The Function Interface

函数把一段代码打包成有名字、可复用的单元。调用者只需关心它的接口（interface），不必关心内部如何实现。接口由三部分组成：

  • 函数名（function name）——用来调用它；
  • 参数列表（parameter list）——它需要什么输入；
  • 返回类型（return type）——它产出什么。
// 计算两个 int 中较大者的函数
int max(int a, int b) {
    if (a > b)
        return a;
    else
        return b;
}

int main() {
    int x = 3, y = 5;
    std::cout << max(x, y);   // 输出 5
}

函数头 int max(int a, int b) 是接口：调用者看到「给我两个 int，还你一个 int」。函数体是内部实现，调用者不必读。

1.2 参数与实参 Parameters versus Arguments

定义

参数（parameter）是函数定义中声明的「占位变量」，如 int a、int b；实参（argument）是调用时实际传入的值，如 max(x, y) 里的 x、y。

调用时，实参被用来初始化参数。二者类型需要匹配（或可隐式转换）。

int add(int a, int b) { return a + b; }

int main() {
    int x = 10, y = 20;
    add(x, y);        // x、y 是实参，绑定到参数 a、b
    add(10, 20);      // 字面量也是实参
    add(x + 1, y);    // 表达式先求值，再作为实参传入
}

1.3 先声明后使用 Declaration Before Use

C++ 要求名字在被使用之前必须已经声明。如果想在 main 里调用一个定义在 main 之后的函数，编译器会因为「还不认识这个名字」而报错。

声明与定义的区别

声明（declaration）只告诉编译器「有这么一个函数，签名是什么」；定义（definition）才给出函数体。一个函数可以被声明多次，但只能定义一次。

#include <iostream>

int add(int a, int b);   // 声明（函数原型 prototype）

int main() {
    std::cout << add(2, 3);   // OK：add 已声明
}

int add(int a, int b) {  // 定义
    return a + b;
}

声明末尾要加分号，定义末尾（函数体后）不加。函数原型是接口的完整表达：int add(int a, int b);。

1.4 返回值与 void Return Values and void

函数用 return 把值交还给调用者。返回类型写在函数名前面。如果函数不需要返回值，返回类型写作 void。

void print_sum(int a, int b) {
    std::cout << a + b << '\n';
    // 没有 return 值；到函数末尾自动返回
}

int main() {
    print_sum(3, 4);   // 打印 7，不产生值
}
注意事项

非 void 函数必须在所有执行路径上都 return 一个值，否则是未定义行为（编译器会警告）。main 函数特例：可以省略 return，编译器隐式返回 0。

1.5 局部变量与作用域 Local Variables and Scope

在函数体（或任意 {} 块）内声明的变量是局部变量（local variable），其作用域（scope）从声明点起，到所在块的 } 结束。离开作用域后变量被销毁，名字失效。

void f() {
    int x = 1;        // x 的作用域从这行开始
    {
        int y = 2;    // y 只在这个内层块内可见
        x += y;
    }
    // std::cout << y;   // 错误：y 已经不在作用域内
    std::cout << x;      // OK：x 仍可见
}

int main() {
    f();
    // std::cout << x;     // 错误：x 是 f 的局部变量
}
要点

局部变量让不同函数可以有同名变量、互不干扰；作用域界定了变量的「生命周期」和「可见性」。理解作用域是理解后续「对象生命周期」「悬垂引用」的前提。

Part 2 · 重载与默认参数 Overloading & Default Arguments

2.1 函数重载 Function Overloading

C++ 允许同名函数共存，只要它们的参数列表不同（参数个数或类型不同）。编译器根据实参类型选出匹配的那个，这一机制叫重载（overloading）。

int   max(int a, int b)     { return a > b ? a : b; }
double max(double a, double b) { return a > b ? a : b; }
int   max(int a, int b, int c) {
    return max(max(a, b), c);
}

int main() {
    max(3, 5);        // 调用 int 版
    max(3.5, 1.2);    // 调用 double 版
    max(1, 2, 3);     // 调用三参数版
}
只看参数，不看返回类型

重载的区分依据只是参数列表。仅返回类型不同的两个同名函数不能共存，因为调用时编译器无法仅凭返回值区分。默认参数造成的「歧义」也会让重载决议失败。

2.2 默认参数 Default Arguments

声明时可以给参数指定默认值，调用时若省略该实参就用默认值。默认参数必须从右往左连续声明。

// 声明处给出默认值
int power(int base, int exp = 2);

int power(int base, int exp) {
    int r = 1;
    for (int i = 0; i < exp; ++i)
        r *= base;
    return r;
}

int main() {
    power(3);       // 等价 power(3, 2) = 9
    power(3, 4);    // = 81
}
两条规则

① 默认值写在声明里（不写在定义里），且一个作用域内只给一次；② 一旦某参数给了默认值，它右边的所有参数都必须有默认值——因为实参是从左往右逐个绑定的。

Part 3 · 引用入门 References

3.1 按值传参的局限 A Copied Parameter

默认情况下 C++ 是按值传递（pass by value）：实参被复制一份交给参数。函数里修改参数，改的是副本，不影响调用者的原变量。

void add_one(int a) {
    a = a + 1;   // 改的是副本
}

int main() {
    int x = 10;
    add_one(x);
    std::cout << x;   // 仍是 10
}

按值传递带来两个问题：一是「想改原变量却改不到」；二是「对象很大时复制开销高」（例如整个 vector）。引用正是为了解决这两点。

3.2 引用是别名 A Reference Is Another Name

定义

引用（reference）是某个已存在对象的别名（alias）。声明时用 &：int& r = x; 表示 r 和 x 指向同一块内存，对 r 的读写就是对 x 的读写。

int main() {
    int x = 10;
    int& r = x;   // r 是 x 的引用（别名）

    r = 20;        // 通过 r 修改 x
    std::cout << x;   // 20

    std::cout << &x << ' ' << &r;   // 地址相同
}
引用必须在声明时初始化

引用一旦绑定到某个对象就终身指向它，因此声明时必须立即初始化，不存在「空的引用」。

3.3 赋值不会重绑引用 Assignment Does Not Rebind a Reference

对引用做赋值，是把值写进它绑定的对象，而不是让它改绑到别的对象。

int main() {
    int a = 1, b = 2;
    int& r = a;   // r 绑定 a
    r = b;         // 把 b 的值(2)赋给 a，r 仍绑定 a

    std::cout << a << ' ' << b << ' ' << r;
    // 2 2 2
}

这与指针不同：指针本身可以改指向，而引用「改不了对象」，只能改对象的值。把引用想成「同一个对象的第二个名字」，很多疑惑自然消失。

Part 4 · 引用参数与 const Reference Parameters & const

4.1 引用参数 Reference Parameters

把形参声明为引用（int& a），就实现了按引用传递（pass by reference）：函数内对 a 的修改直接作用到实参上，且不产生复制。

void add_one(int& a) {
    a = a + 1;   // 直接改调用者的变量
}

int main() {
    int x = 10;
    add_one(x);
    std::cout << x;   // 11
}

引用参数常见用途：① 让函数「返回多个结果」；② 避免复制大对象（如 vector）。

4.2 什么能绑定到 int& What Can Bind to int&?

非常量引用 int& 只能绑定到可修改的左值（lvalue）——一个真正存在、有名字、可被赋值的对象。它不能绑定到：

  • 字面量：add_one(5) ❌
  • 临时值（右值）：add_one(x + 1) ❌
  • 不同类型需要转换的值：add_one(3.5) ❌（double 要先转成临时 int）
void f(int& x) { x += 1; }

int main() {
    int a = 1;
    f(a);        // OK：a 是左值
    // f(2);     // 错误：不能绑定字面量
    // f(a + 1); // 错误：不能绑定临时值
}

4.3 const 与只读引用 const and Read-only References

定义

const 引用（const reference）写作 const int&，是「只读」别名：可以通过它读值，但不能通过它修改。它比 int& 更宽松，可以绑定到字面量、临时值，因为它承诺「不改」。

void print(const int& x) {
    std::cout << x;   // 只读
    // x += 1;         // 错误：const 引用不可修改
}

int main() {
    int a = 5;
    print(a);      // OK
    print(10);     // OK：const 引用可绑定字面量
    print(a + 1);  // OK
}
何时用 const 引用

函数只需读、不需改参数时，用 const T&：既避免复制大对象的开销，又明确表达「我不会改你的数据」。这是 C++ 的默认最佳实践。

4.4 读容器而不复制 Read a Container Without Copying It

如果按值传入 vector，整个容器会被复制，非常昂贵。用 const vector<int>& 就能「只读、零复制」。

#include <vector>
#include <iostream>

int sum(const std::vector<int>& v) {
    int s = 0;
    for (int x : v)
        s += x;
    return s;
}

int main() {
    std::vector<int> v = {1, 2, 3, 4};
    std::cout << sum(v);   // 10，v 没有被复制
}

4.5 选择参数类型 Choosing a Parameter Type

选择参数类型时，按「是否需要修改」和「对象是否昂贵」两个维度决定：

需求参数类型说明
只读 + 小型（int/double…）T（按值）复制便宜，语义清晰
只读 + 大型（容器/字符串）const T&避免复制
需要修改实参T&按引用传递，直接改原对象

经验法则：先想「要不要改」——不改就加 const；再想「大不大」——大对象用引用避免复制。

Part 5 · 返回与对象生命周期 Return & Object Lifetime

5.1 返回值与对象生命周期 Return Values and Object Lifetime

函数可以按值返回（复制一份出去）或返回引用。返回引用要格外小心：绝不能返回指向局部变量的引用，因为局部变量在函数返回时就被销毁了，剩下的引用就是悬垂引用（dangling reference）。

int& bad() {
    int x = 10;
    return x;   // 错误！返回局部变量的引用
}               // x 在这里被销毁，引用悬空

const std::string& longer(const std::string& a, const std::string& b) {
    return a.size() >= b.size() ? a : b;   // OK：返回的仍是调用者的对象
}
定义

悬垂引用（dangling reference）：指向一个已经结束生命周期的对象的引用。访问它属于未定义行为（undefined behavior），可能读到垃圾值、可能崩溃。

安全做法：返回值（int、std::string…）让编译器复制/移动，或返回调用者传入的引用（像 longer 那样）。

5.2 带引用的范围 for Range-based Loops with References

范围 for 循环默认把每个元素复制到循环变量。要原地修改元素，用引用；要只读遍历大对象又不想复制，用 const 引用。

std::vector<int> v = {1, 2, 3};

for (int x : v)        // 副本：改 x 不影响 v
    x *= 10;

for (int& x : v)       // 引用：原地修改 v
    x *= 10;

for (const int& x : v) // const 引用：只读、零复制
    std::cout << x << ' ';
用 auto 时的习惯

惯用法：for (auto& x : v) 表示「可改」，for (const auto& x : v) 表示「只读」。除非元素很小，否则默认用引用，避免无谓复制。

5.3 Python / Java / C++ 参数模型 Parameters in Three Languages

三种语言对「传参」的默认行为不同，理解差异能避免把 Python/Java 的习惯带进 C++：

语言默认模型能否原地修改传入对象
Python对象引用 + 不可变/可变之分int/str 不行；list/dict 可改内容
Java按值传「引用」（对象句柄）对象内容可改，但重绑参数不影响实参
C++按值（复制）只有显式写 T& 才原地修改

核心差异：C++ 的默认行为是复制，想要「引用语义」必须显式写 &；而 Python/Java 里对象变量天然是引用，反而「复制」需要显式。

Part 6 · 迭代器入门 Iterators

6.1 为什么需要迭代器 Why Do We Need Iterators?

不同容器（vector、string、list…）内部结构不同，如何统一地「遍历、查找、排序」？迭代器（iterator）提供了统一的抽象：它像一个「指向容器元素的指针」，无论底层是数组还是链表，都能用同一套接口访问。

定义

迭代器是「指向容器中某个位置的泛化指针」。通过它可以访问元素的值（解引用 *it），并移动到下一个位置（++it）。

6.2 begin() 与 end() begin() and end()

每个容器都有 begin() 返回「第一个元素」的迭代器，end() 返回「最后一个元素之后」的迭代器（哨兵，不指向任何元素）。区间 [begin, end) 左闭右开。

std::vector<int> v = {10, 20, 30};
auto it = v.begin();   // 指向 10
auto e  = v.end();     // 哨兵：指向 30 之后
end() 不是最后一个元素

end() 是「尾后」位置，不能解引用。它只是循环的终止标记。空容器中 begin() == end()。

6.3 写迭代器循环 Write an Iterator Loop

经典迭代器遍历：从 begin() 出发，每次 ++it，直到等于 end()。

std::vector<int> v = {10, 20, 30};

for (auto it = v.begin(); it != v.end(); ++it)
    std::cout << *it << ' ';   // 10 20 30
  • *it —— 解引用，得到当前元素（可读可写）；
  • ++it —— 前进到下一个位置；
  • it != v.end() —— 判断是否到末尾。

6.4 位置 vs 值 Position versus Value

迭代器本身是「位置」，*it 才是「值」。二者是两回事：

std::vector<int> v = {7, 8, 9};
auto it = v.begin();   // it 是位置（指向 7）
*it = 70;              // 通过位置改值：v 变成 {70, 8, 9}
++it;                  // 位置前进到 8
int val = *it;         // 读出值 8

很多新手混淆「把迭代器往前挪」和「把值加一」。记住：++it 动位置，(*it)++ 或 *it += 1 才动值。

Part 7 · 算法与区间 Algorithms & Ranges

7.1 查找元素 Find an Element

std::find(first, last, value) 在区间 [first, last) 中查找 value，返回第一个匹配位置的迭代器；找不到返回 last。

std::vector<int> v = {1, 4, 2, 4, 5};
auto it = std::find(v.begin(), v.end(), 4);
if (it != v.end())
    std::cout << "found at index " << (it - v.begin());
else
    std::cout << "not found";

7.2 string::find vs std::find Two Kinds of find

字符串有成员函数 s.find(...)，返回的是下标（找不到返回 std::string::npos）；而 std::find 是通用算法，返回迭代器。

std::string s = "hello";
std::size_t pos = s.find('l');        // 返回下标 2（找不到为 npos）

auto it = std::find(s.begin(), s.end(), 'l');   // 返回迭代器
// it - s.begin() == 2
别搞混返回值

string::find → size_t 下标；std::find → 迭代器。两者「找不到」的哨兵也不同：npos vs end()。

7.3 在普通数组里查找 Find in an Ordinary Array

算法对迭代器工作，而指针天然是数组的迭代器。所以 std::find 也能用在 C 风格数组上，用「首指针」和「尾后指针」表达区间。

int a[] = {1, 2, 3, 4, 5};
int* it = std::find(a, a + 5, 3);
// 或用 std::begin(a), std::end(a)
auto it2 = std::find(std::begin(a), std::end(a), 4);

7.4 让算法干活：sort / reverse Let an Algorithm Do the Work

与其手写循环，不如调用标准算法——更短、更不易错、意图更清晰。

std::vector<int> v = {4, 1, 3, 2};

std::sort(v.begin(), v.end());    // 升序：1 2 3 4
std::reverse(v.begin(), v.end()); // 逆序：4 3 2 1

7.5 算法作用于区间 Algorithms Work on Ranges

几乎所有算法都接收「一对迭代器」[first, last) 表示待处理的区间，且不会触碰区间之外的元素。这是标准库算法的统一约定。

std::vector<int> v = {5, 1, 9, 2, 8, 3};

// 只排序前三个：5 1 9 → 1 5 9
std::sort(v.begin(), v.begin() + 3);
// 结果：1 5 9 2 8 3

7.6 常用区间算法 Common Range Algorithms

几个高频算法（均在 <algorithm> 或 <numeric>）：

算法作用示例
std::find查找值，返回迭代器find(b, e, v)
std::count统计值出现次数count(b, e, v)
std::sort升序排序sort(b, e)
std::reverse原地逆序reverse(b, e)
std::min_element最小元素的迭代器min_element(b, e)
std::max_element最大元素的迭代器max_element(b, e)
std::accumulate求和（numeric）accumulate(b, e, 0)

7.7 迭代器算术 Iterator Arithmetic

对随机访问迭代器（如 vector、string、数组的迭代器），可以像指针一样做算术：

std::vector<int> v = {10, 20, 30, 40, 50};
auto it = v.begin();

it += 2;              // 前进 2 步 → 指向 30
it - 1;               // 回退 1 步
int idx = it - v.begin();   // 迭代器相减得「距离」（下标）
v.end() - v.begin();        // = 5，元素个数
不是所有迭代器都能算术

链表 list 的迭代器只能 ++，不能 + n 或相减。能随意跳跃的是随机访问迭代器（random access iterator）。写通用代码时按「最弱的迭代器」来假设。

Part 8 · 迭代器端点 Iterator Endpoints

8.1 端点对照表 The Endpoint Table

每个容器提供多组端点迭代器，覆盖「正向 / 反向」×「可写 / 只读」四种组合：

端点方向可写？含义
begin() / end()正向可写首元素 / 尾后
cbegin() / cend()正向只读const 版本
rbegin() / rend()反向可写末元素 / 首前
crbegin() / crend()反向只读const 反向

8.2 从 rbegin() 反向遍历 Starting from rbegin()

rbegin() 指向最后一个元素，rend() 是「第一个元素之前」的哨兵。对反向迭代器 ++ 是往数组头部走。

std::vector<int> v = {1, 2, 3, 4, 5};

for (auto it = v.rbegin(); it != v.rend(); ++it)
    std::cout << *it << ' ';   // 5 4 3 2 1

8.3 反向迭代器与算法 Algorithms with Reverse Iterators

标准算法只认「一对迭代器」，所以把 rbegin()/rend() 传进去，就能让算法反向工作。

std::string s = "hello";

std::sort(s.rbegin(), s.rend());    // 从大到小：o l l h e
std::reverse(s.rbegin(), s.rend()); // 再反向一次又变回正向

8.4 只读迭代器 Read-only Iterators

cbegin()/cend()（和 crbegin()/crend()）返回 const 迭代器，解引用得到只读引用，防止误改容器。

const std::vector<int>& cv = v;
for (auto it = cv.begin(); it != cv.end(); ++it)
    std::cout << *it;   // 只读

for (auto it = v.cbegin(); it != v.cend(); ++it)
    std::cout << *it;   // 即使 v 可写，也强制只读

Part 9 · 谓词与比较器 Predicates & Comparators

9.1 谓词 Predicates

定义

谓词（predicate）是返回 bool 的函数（或可调用对象），回答「这个元素满足某条件吗」。例如「是偶数吗」「是正数吗」。

bool is_even(int x) {
    return x % 2 == 0;
}

bool is_positive(int x) {
    return x > 0;
}

9.2 函数作为算法参数 Functions as Algorithm Arguments

很多算法接受一个谓词作为额外参数，从而把「找什么 / 数什么」交给调用者决定：

std::vector<int> v = {1, 2, 3, 4, 5, 6};

auto it = std::find_if(v.begin(), v.end(), is_even);
// 返回第一个偶数 2 的迭代器

int cnt = std::count_if(v.begin(), v.end(), is_positive);
// 统计正数个数 = 6
  • find_if(b, e, pred) —— 找第一个满足谓词的元素；
  • count_if(b, e, pred) —— 数满足谓词的元素个数。

9.3 自定义排序 Custom Sort Order

std::sort 默认升序，但可以传入比较器（comparator）自定义顺序。比较器 cmp(a, b) 应返回「a 是否应排在 b 之前」。

bool descending(int a, int b) {
    return a > b;   // a 排在 b 前，当 a 更大
}

std::vector<int> v = {3, 1, 4, 1, 5};
std::sort(v.begin(), v.end(), descending);
// 5 4 3 1 1

9.4 排序记录 Sorting Records

比较器常用于排序「记录」（如 struct 或 pair）。例如按第一个字段排序、相同则按第二个字段。

struct Student {
    std::string name;
    int score;
};

bool by_score(const Student& a, const Student& b) {
    return a.score > b.score;   // 分数高者在前
}

std::vector<Student> s = {...};
std::sort(s.begin(), s.end(), by_score);

9.5 一致的比较器 A Consistent Comparator

严格弱序

比较器必须满足严格弱序（strict weak ordering）：① 反自反——cmp(x, x) 必为假；② 反对称——若 cmp(a,b) 真则 cmp(b,a) 假；③ 传递——若 cmp(a,b) 且 cmp(b,c)，则 cmp(a,c)。等价元素（互相都不「在前」）视作相等。

常见错误

写 return a <= b; 而不是 a < b 会违反反自反性，导致 sort 行为未定义、甚至崩溃。相等元素应返回 false。多关键字时用「先比主键，不等则返回；相等再比次键」保证传递性。

// 正确：先比第一键，相等再比第二键
bool cmp(const std::pair<int,int>& a, const std::pair<int,int>& b) {
    if (a.first != b.first)
        return a.first < b.first;
    return a.second < b.second;
}

Part 10 · 修改容器 Modifying Containers

10.1 在指定位置插入 / 删除 Insert and Erase at a Position

vector 支持在迭代器指定位置插入或删除元素。insert(pos, value) 在 pos 前插入；erase(pos) 删除 pos 处的元素。

std::vector<int> v = {1, 2, 4, 5};

v.insert(v.begin() + 2, 3);   // {1, 2, 3, 4, 5}
v.erase(v.begin());            // {2, 3, 4, 5}
删除任意位置是 O(n)

vector 是连续内存，中间插入/删除需要把后面元素整体搬移，平均 O(n)。频繁在中间增删应改用 list 等结构。

10.2 旧迭代器可能失效 Old Iterators May Become Invalid

插入/删除（尤其是触发 vector 扩容）会破坏旧迭代器，因为底层内存可能被重新分配、元素位置改变。继续使用失效的迭代器是未定义行为。

std::vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin();

v.push_back(6);   // 可能触发扩容，it 失效！
// std::cout << *it;   // 危险：未定义行为

10.3 读契约而不是读名字 Read the Contract, Not Just the Name

不要凭函数名猜测行为，要读文档里的契约（contract）：它接收什么、返回什么、有哪些前置条件、哪些操作会使迭代器失效。

// erase(pos) 返回指向被删元素之后位置的迭代器
// 且会使 pos 及其后的迭代器失效

std::vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin() + 2;      // 指向 3
it = v.erase(it);             // 删除 3，it 现在指向 4
// v = {1, 2, 4, 5}

10.4 边迭代边删除 Erasing While Iterating

要边遍历边删除，应利用 erase 的返回值（指向下一个有效元素），而不是盲目 ++it：

std::vector<int> v = {1, 2, 3, 2, 4, 2};

for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 2)
        it = v.erase(it);   // 删除并前进，不要额外 ++
    else
        ++it;
}
// v = {1, 3, 4}
经典坑

写 for (auto it = v.begin(); it != v.end(); ++it) 再在循环里 erase 会跳过元素或越界。要么用上面「返回值更新」的写法，要么用后面提到的 erase-remove 惯用法。

11.1 680 验证回文串 II Valid Palindrome II

题目

给定字符串 s，判断在最多删除一个字符后能否成为回文串。例如 "abca" 删除 'b' 得 "aca" 是回文。

思路：双指针从两端向中间靠拢。当遇到不相等的一对字符时，有两种选择：删左边的或删右边的，分别检查剩余部分是否回文；只要有一个成立即可。

bool is_pal(const std::string& s, int l, int r) {
    while (l < r) {
        if (s[l] != s[r]) return false;
        ++l; --r;
    }
    return true;
}

bool validPalindrome(std::string s) {
    int l = 0, r = (int)s.size() - 1;
    while (l < r) {
        if (s[l] != s[r])
            return is_pal(s, l + 1, r) || is_pal(s, l, r - 1);
        ++l; --r;
    }
    return true;
}
易错点

① 只能删一个字符——第一次不匹配时分别尝试两种删除即可，不用递归深入；② 子串检查仍是回文判断，可复用同一个 is_pal 函数，体现「函数复用」。

11.2 242 有效的字母异位词 Valid Anagram

题目

判断两个字符串 s 和 t 是否互为字母异位词（anagram）——即用完全相同的字母、每个字母出现次数相同（顺序可不同）。

思路：统计每个字符的出现次数并比较。这里结合本讲知识，用 std::sort 把两个字符串各自排序后比较是否相等。

bool isAnagram(std::string s, std::string t) {
    if (s.size() != t.size()) return false;
    std::sort(s.begin(), s.end());
    std::sort(t.begin(), t.end());
    return s == t;
}

也可以用计数数组 count[26]，时间复杂度 O(n)，但排序法更直接地示范了「让算法干活」的思想。

11.3 1356 按二进制 1 的个数排序 Sort Integers by The Number of 1 Bits

题目

给一个整数数组，按每个数二进制表示中 1 的个数升序排序；若 1 的个数相同，则按数值升序。例如 [0,1,2,3,4,5,6,7,8] 排序后 [0,1,2,4,8,3,5,6,7]。

思路：这题是「两个排序关键字」的典型应用——主键是 popcount(x)，次键是 x 本身。写一个一致的比较器即可。

int popcount(int x) {
    return __builtin_popcount(x);   // GCC/Clang 内置：数 1 的个数
}

bool cmp(int a, int b) {
    int ca = popcount(a), cb = popcount(b);
    if (ca != cb)
        return ca < cb;    // 主键：1 的个数
    return a < b;          // 次键：数值本身
}

std::vector<int> sortByBits(std::vector<int>& arr) {
    std::sort(arr.begin(), arr.end(), cmp);
    return arr;
}
两个排序关键字

比较器先比「1 的个数」，不等就返回；相等再比「数值」。这样保证传递性，是稳定、正确的写法。若只写 return popcount(a) < popcount(b) 会漏掉次键，相等元素的顺序不确定。

11.4 用 lambda 写比较器 Another Way to Write the Comparator

只为排序写一个独立函数有些啰嗦，lambda 表达式（lambda expression） 可以就地定义匿名函数，尤其适合临时的小比较器。

std::vector<int> arr = {0,1,2,3,4,5,6,7,8};

std::sort(arr.begin(), arr.end(),
    [](int a, int b) {
        int ca = __builtin_popcount(a);
        int cb = __builtin_popcount(b);
        if (ca != cb) return ca < cb;
        return a < b;
    });
lambda 语法

[捕获列表](参数列表) { 函数体 }。捕获列表 [] 为空表示不捕获外部变量；[&] 按引用捕获、[=] 按值捕获。lambda 的类型是编译器生成的匿名类型，通常配合 auto 或直接传给算法。

3.1 存储期 Storage Duration

4.4 强制指针转换 A Forced Pointer Cast

int a[6] = {1, 2, 3, 4, 5, 6};
int* p = a;
int (*row)[3] = (int (*)[3])p;
++row;   // 编译通过，但这是未定义行为

转换能编译，但 ++row 是未定义行为。典型构建可能前进 3 × sizeof(int) 字节、落在 a[3] 的地址上，但 C++ 不保证这个结果。数组里有六个 int，不是两个「行对象」。转换只改指针类型，不改内存里的对象——指针类型控制移动和访问，它必须和实际使用的对象匹配。

值1234567

从原序列读到独立结果，再把结果写回。立刻写回可能覆盖掉后面还要用的值。

方法二：三次反转。最后 k 个值应该排到前 n − k 个值前面：

阶段序列

反转整个数组7 6 5 4 3 2 1

两块交换位置，最后两次反转恢复各块内部顺序。

易错点

右旋和左旋不同；第一部分是 [begin, begin + k)；要测试 k = 0、k = n、k > n 和单个元素。

Part 1 · 为什么需要链表 Why Linked Lists

1.1 音乐播放列表：在中间插入 Inserting Without Shifting

想象一个音乐 App 的播放列表。用数组存放时，若想在歌 2 和歌 3 之间插进一首新歌，就必须把后面的所有歌整体向后搬一格腾出空位——数组的「连续」既是它的优点（按下标 O(1) 访问），也是它的负担（中间插入/删除要 O(n) 搬家）。

如果每个「歌」单元额外记下「下一首歌在哪里」，那么插入一首新歌就只是改两个指针：让新歌指向原来排在它后面的歌，再让它的前一首歌指向它。中间的歌一个都不用动。

1.2 后退 / 前进：双向 Back and Forward

浏览器的「后退 / 前进」按钮、代码编辑器的撤销/重做，都要求既能往前走、也能往回走。单向的链只能朝一个方向走（往 next）；若每个节点再记下它的前驱 prev，就得到双向链表（doubly linked list），可以朝两个方向自由移动。

1.3 LRU 缓存 Keeping Recently Used Data

LRU（Least Recently Used，最近最少使用）缓存：当缓存满了要淘汰时，淘汰最久没被用过的数据。每次访问一个条目，就把它移到最前面——这需要「快速把一个元素从中间摘出来、再插到头部」。链表（尤其是双向链表）正好擅长这件事。

1.4 轮转调度 Round-Robin Processing

操作系统把 CPU 时间轮流分给各个进程（round-robin 轮转调度）。处理完最后一个进程后要回到第一个继续。把链表的尾巴接回头部，就得到循环链表（circular linked list），天然适合「一圈一圈轮流」的场景。

1.5 真实软件中的链表 Linked Lists in Real Software

  • Java 的 LinkedHashMap：内部同时用哈希表（快速查找）和双向链表（记住插入顺序），遍历时按插入顺序输出。
  • Linux 内核：大量用链表组织进程、文件、内存页等，其中一个经典设计是「把链表节点嵌进各种结构体里」（struct list_head），一套链表代码到处复用。

Part 2 · 链表基础 Nodes and Links

2.1 节点与链接 Nodes and Links

链表由一个个节点（node）组成。每个节点存两样东西：一个值（value），和一个指向下一个节点的指针 next。用 C++ 结构体表示：

struct Node {
    int value;   // 本节点存的数据
    Node* next;  // 指向下一个节点（结尾为 nullptr）
};

最后一个节点的 next 是 nullptr，表示「到这里结束」。整条链只需要一个头指针（head）就能找到所有节点：从 head 出发，沿着 next 一路走到底。

图：单链表结构——head 指向第一个节点（10），每个节点的 next 指向后一个节点，最后节点（30）的 next 为 nullptr。整条链只靠 head 就能串起来。

2.2 数组 vs 链表 Arrays and Linked Lists

对比项数组 array链表 linked list
存储方式连续存放节点散落，用指针串起来
访问第 i 个元素O(1)（按下标直取）O(i)（沿 next 走 i 步）
中间插入 / 删除O(n)（要搬动后面的元素）O(1)（改几个指针，但要先找到位置）
额外空间无每个节点多存一个指针

一句话：数组赢在随机访问，链表赢在中间的插入/删除不用搬家。

2.3 头指针与空链表 A Node and a Head Pointer

空链表就是「还没有任何节点」，用 head == nullptr 表示。判断链表是否为空、遍历的结束条件，都围绕这个约定展开：

Node* head = nullptr;      // 空链表

if (head == nullptr) ...   // 判断空
Node* p = head;            // 从头开始
while (p != nullptr) ...   // 走到末尾

2.4 沿链移动 p = p->next Following the Links

指针 p 想要「走到下一个节点」，写的是 p = p->next;（把 p 改写成它所指节点的 next）。注意：p++ 不会跟着 next 走——链表节点不是连续存放的，p++ 只会让 p 指向「地址往后移一个 Node 大小」的地方，通常是个错误位置。链表里移动的唯一正道是 p = p->next。

怎么理解

数组里 a[i+1] 之所以能找到下一个元素，是因为它们在内存里正好挨着；链表节点在内存里是散开的，下一个节点不是「地址 +1」，而是「当前节点 next 字段里存的那个地址」。所以一定要顺着 next 走。

Part 3 · 单链表操作 Singly Linked List Operations

3.1 构建单链表 buildList Building a Singly Linked List

给定一个 vector<int>，逐个元素接到链表尾部。用 head 记第一个节点、tail 记最后一个节点，每个新节点插到 tail 之后：

Node* buildList(const vector<int>& values) {
    Node* head = nullptr;
    Node* tail = nullptr;
    for (int v : values) {
        Node* fresh = new Node{v, nullptr};
        if (head == nullptr) {
            head = tail = fresh;       // 第一个节点
        } else {
            tail->next = fresh;       // 接到尾巴后面
            tail = fresh;              // 尾巴前移
        }
    }
    return head;
}

3.2 遍历 Traversing a List

for (Node* p = head; p != nullptr; p = p->next)
    cout << p->value << ' ';

这是链表的「标准 for 循环」：初始化指向头，条件是没到末尾，步进是 p = p->next。三个要素一一对应。

3.3 查找 findNode Searching a List

Node* findNode(Node* head, int value) {
    for (Node* p = head; p != nullptr; p = p->next)
        if (p->value == value)
            return p;       // 找到了，返回这个节点
    return nullptr;         // 走完没找到
}

3.4 插入节点 Inserting a Node

在已知节点 p 之后插入一个新值。两步：先让新节点的 next 接上 p 原来的后继，再把 p 的 next 指向新节点。

Node* fresh = new Node{value, p->next};  // ① 新节点先指向 p 的后继
p->next = fresh;                          // ② p 再指向新节点

顺序不能反：如果先执行 p->next = fresh，p 原来的后继就「断线」找不回来了。

图：在 p 之后插入 fresh——①fresh 先接上 p 原来的后继（30）；②p 再改指向 fresh。顺序反了就会丢掉 30。

3.5 头插 pushFront Inserting at the Head

在链表最前面插入，需要修改 head 本身，所以 head 用引用参数 Node*& head：

void pushFront(Node*& head, int value) {
    head = new Node{value, head};   // 新节点的 next 指向旧 head
}

一行搞定：新节点接管旧头，然后自己成为新头。空链表（head == nullptr）也天然适用——新节点的 next 就是 nullptr。

3.6 删除头节点 popFront Removing the Head

void popFront(Node*& head) {
    if (head == nullptr) return;   // 空链表，无事可做
    Node* victim = head;
    head = head->next;             // 头前移到下一个
    delete victim;                 // 释放旧头
}

先让 head 前移，再释放旧头。顺序也不能反——先 delete 就没法拿到 head->next 了。

3.7 删除节点 eraseAfter Removing a Node

单链表删节点需要它的前驱：让前驱 p 跳过它直接指向它的后继，再释放它。

void eraseAfter(Node* p) {
    if (p == nullptr || p->next == nullptr) return;  // 没有可删的
    Node* victim = p->next;
    p->next = victim->next;    // 绕过 victim
    delete victim;
}

关键：先把 p->next 改成 victim->next（绕过），再 delete victim。delete 之后绝不能再读 victim->next——那已经是悬垂访问。

3.8 释放整条链 clearList Releasing a List

void clearList(Node*& head) {
    while (head != nullptr) {
        Node* savedNext = head->next;  // 先把后继地址存下来
        delete head;                    // 释放当前节点
        head = savedNext;               // 移到后继继续
    }
}

核心心法的第一次体现：释放节点之前，先把它的后继地址存下来（savedNext）。否则 delete head 之后，head->next 就是悬垂访问，链条就断了。

3.9 选择题：插入顺序 Insertion: Multiple Choice

例题 · 插入顺序

把 fresh 插到 p 和它原来的后继之间，下面哪种顺序正确？

A.  p->next = fresh;
    fresh->next = p->next;

B.  fresh->next = p->next;
    p->next = fresh;

答案：B。必须先让 fresh 接上 p 原来的后继，再让 p 指向 fresh。A 里第一条语句 p->next = fresh 之后，p->next 已经是 fresh 了，第二条 fresh->next = p->next 会让 fresh 指向它自己，形成自环，原来的后继彻底丢失。

3.10 选择题：浙大删除题 Deletion: Multiple Choice

例题 · 浙江大学考研题

初始链表：1 → 5 → 2 → 3 → 6。执行下面代码后，剩下哪些值？

Node* p = head;
while (p->next != nullptr) {
    if (p->next->value <= p->value) {
        Node* victim = p->next;
        p->next = victim->next;
        delete victim;
    } else
        p = p->next;
}

A. 1, 2, 3, 6　　B. 1, 5, 6　　C. 1, 6　　D. 1, 5, 2, 3, 6

答案：B（1, 5, 6）。这段代码「沿链走，只要后继 ≤ 当前节点就删掉后继，否则前进一步」。逐段看：

  • p = 1，后继 5 > 1，不删，p 前进到 5；
  • p = 5，后继 2 ≤ 5，删掉 2；此时 p 的新后继变成 3；
  • p 仍在 5，后继 3 ≤ 5，再删掉 3；新后继是 6；
  • p 仍在 5，后继 6 > 5，不删，p 前进到 6；
  • p = 6，后继是 nullptr，循环结束。

剩下 1 → 5 → 6。易错点：删除一个节点后 p 不要前进，因为新顶上来的后继可能也要删（5 连删 2、3 正是如此）。

Part 4 · 反转链表 Reverse Linked List（LeetCode 206）

4.1 思路：三指针 Three Pointers

反转单链表 = 把每个节点的 next 反过来指向它的前驱。因为反转后「后继」就断了，所以要用三个指针：

  • previous：已经反转好的前缀的头；
  • current：正在处理的节点；
  • savedNext：还没处理的后缀（先存下来，防止断线）。

4.2 逐步走查 Step by Step

初始 10 → 20 → 30 → 40。每一步做四件事：

Node* savedNext = current->next;  // ① 存下后继，保住后缀
current->next = previous;        // ② 当前节点反转，指向前驱
previous = current;              // ③ previous 前进到当前
current = savedNext;             // ④ current 前进到后缀

以「反转 20 这条链」为例：previous 停在 10（已反转），current 在 20，savedNext 存下 30。② 让 20->next 指向 10，③④ 各自前进一格，如此反复，直到 current 走到 nullptr，此时 previous 就是新头。

图：反转一步——previous 停在已反转的前缀（10），current 在 20，先存住后继 30（savedNext），再让 20 指向 10，最后两个指针各前进一格。

4.3 代码与剖析 Program Anatomy

Node* reverseList(Node* head) {
    Node* previous = nullptr;
    Node* current = head;
    while (current != nullptr) {
        Node* savedNext = current->next;   // 先保存后继
        current->next = previous;          // 反转当前节点
        previous = current;                // 两个指针前进
        current = savedNext;
    }
    return previous;                       // 循环结束时 previous 即新头
}

解剖要点：previous 从 nullptr 开始（原头的 next 反转到空）；每轮先存后继再改指针；循环结束返回 previous 而非 current（此时 current 已越过末尾）。

4.4 易错点 Easy to Get Wrong

易错点
  • 把返回值写回 head：head = reverseList(head);，否则调用方拿不到新头。
  • 测试边界：空链表、单个节点、两个节点都要测。
  • 释放：反转后要从新头开始释放整条链。

Part 5 · 双向链表 Doubly Linked Lists

5.1 节点结构 DNode / DList Nodes with a Predecessor

双向链表每个节点多存一个 prev，指向前驱。这样已知一个节点，就能直接找到它的前驱和后继。

struct DNode {
    int value;
    DNode* prev;
    DNode* next;
};

struct DList {
    DNode* head = nullptr;   // 头
    DNode* tail = nullptr;   // 尾
};

DList 只是把两个端点指针打包在一起，方便同时维护头尾。

图：双向链表——每个节点同时有 prev 和 next 两个指针，可以朝两个方向遍历；head 和 tail 标记两端。

5.2 追加 append Appending

void append(DList& list, int value) {
    DNode* fresh = new DNode{value, list.tail, nullptr};
    if (list.tail != nullptr) list.tail->next = fresh;
    else list.head = fresh;      // 空链表：head 也要设
    list.tail = fresh;
}

新节点的 prev 指向旧尾；旧尾的 next 指向新节点；最后 tail 前移。空链表时把 head 一并设上。

5.3 双向遍历 Traversing in Both Directions

for (DNode* p = list.head; p != nullptr; p = p->next)  // 正向 10 20 30
    cout << p->value << ' ';
for (DNode* p = list.tail; p != nullptr; p = p->prev)  // 反向 30 20 10
    cout << p->value << ' ';

两个方向的结束条件相同：都是 p != nullptr。正向沿 next 走，反向沿 prev 走。

5.4 在节点前插入 insertBefore Inserting Between Two Nodes

void insertBefore(DList& list, DNode* pos, int value) {
    if (pos == nullptr) { append(list, value); return; }  // 空位置 = 追加
    DNode* fresh = new DNode{value, pos->prev, pos};      // 新节点前后接好
    if (pos->prev != nullptr) pos->prev->next = fresh;   // 前驱的后继接新节点
    else list.head = fresh;                                // 插到最前：更新 head
    pos->prev = fresh;                                     // pos 的前驱改成新节点
}

5.5 删除指定节点 eraseNode Removing a Given Node

void eraseNode(DList& list, DNode* node) {
    if (node == nullptr) return;
    if (node->prev != nullptr) node->prev->next = node->next;   // 前驱绕过后继
    else list.head = node->next;                                 // 删的是头
    if (node->next != nullptr) node->next->prev = node->prev;   // 后继绕回前驱
    else list.tail = node->prev;                                 // 删的是尾
    delete node;
}

双向链表删节点不需要前驱参数——节点自己就带着 prev 和 next。先把左右邻居重新接好，再 delete 节点。

5.6 头 / 尾 / 单节点的边界 Head, Tail, and a Single Node

操作之后的 head之后的 tail
向空链表插入新节点新节点
删除多个节点中的第一个旧头的后继不变
删除多个节点中的最后一个不变旧尾的前驱
删除唯一节点nullptrnullptr
注意事项

非空链表里，head->prev 和 tail->next 都是 nullptr。每次改动端点（头或尾）都要检查空链表和单节点两种情况——这是链表 bug 的高发区。

5.7 释放 clearDoubly Releasing a Doubly Linked List

void clearDoubly(DList& list) {
    while (list.head != nullptr) {
        DNode* savedNext = list.head->next;
        delete list.head;
        list.head = savedNext;
    }
    list.tail = nullptr;
}

清理时只沿 next 走，不要用旧的 prev 链接（有些节点可能已经悬垂）。最后把 tail 也置空。

5.8 Move to Front 填空题 Stanford Final Exam

例题 · 斯坦福大学期末考试

把节点 6 移到最前面（只改链接，不 new 不 delete）。初始 8 ↔ 3 ↔ 6，目标 6 ↔ 8 ↔ 3。

if (front == toMove) return;
// 先把 toMove 从邻居中摘出来
toMove->prev = ___(1)___;
toMove->next = ___(2)___;
front->prev = toMove;
front = ___(3)___;

答案：(1) nullptr，(2) front，(3) toMove。

理解：把 toMove 摘出来——它的 prev 置空（变成新头，没有前驱）、next 指向旧 front（原 8）；再把旧 front 的 prev 改成 toMove；最后 front 前移到 toMove。完整过程还需要在摘除前用 toMove->prev->next = toMove->next 和 toMove->next->prev = toMove->prev 把原邻居接好。

验证双向正确性：只看正向顺序不够——正向输出正确不证明 prev 也正确，要正反两个方向都验一遍。

Part 6 · 循环链表 Circular Linked Lists

6.1 概念与单尾指针 A Circle with One Tail Pointer

循环链表把最后一个节点的 next 接回头部，形成一圈。这里实现的是「单链环」，并且只用一个 tail 指针：因为 head = tail->next，有了 tail 就同时有了头。

6.2 线性 vs 循环结尾 Linear versus Circular Endings

方向线性结尾循环结尾
单链表last->next 是 nullptrlast->next 是 head
双向链表head->prev 和 tail->next 是 nullptrhead->prev 是 tail，tail->next 是 head

6.3 构建 circlePushFront Building a Circular List

void circlePushFront(Node*& tail, int value) {
    Node* fresh = new Node{value, nullptr};
    if (tail == nullptr) {
        fresh->next = fresh;   // 第一个节点：自己指向自己
        tail = fresh;
    } else {
        fresh->next = tail->next;   // 新节点接上原头
        tail->next = fresh;          // 尾接上新节点
    }
}

第一个节点形成「自己指向自己」的单节点环；之后每个新节点插到 head 位置（tail 之后）。

6.4 头插与尾插 Inserting at Front and Back

头插就是 circlePushFront（保持 tail 不变，新头是 tail->next）。尾插则复用头插再移动 tail：

void circlePushBack(Node*& tail, int value) {
    circlePushFront(tail, value);   // 先插到 tail 之后（即头部）
    tail = tail->next;              // 再把 tail 移到新节点上
}

因为「tail 之后」就是 head，插到 head 之后再让 tail 跟上，就等于插到了尾部。

6.5 一整圈遍历 One Complete Lap

环没有 nullptr 终点，遍历要「回到起点就停」。用 do-while：

if (tail != nullptr) {
    Node* start = tail->next;   // 从 head 出发
    Node* p = start;
    do {
        cout << p->value << ' ';
        p = p->next;
    } while (p != start);        // 回到起点，正好一圈
}

为什么是 do-while 而不是 while？因为要在处理完第一个节点之后才判断是否回到起点；否则一开始 p == start 就会直接跳出。

6.6 插入 circleInsertAfter / 删除 circleEraseAfter Inserting and Removing

void circleInsertAfter(Node*& tail, Node* p, int value) {
    Node* fresh = new Node{value, p->next};
    p->next = fresh;
    if (p == tail) tail = fresh;   // 在尾后插 = 变成新尾
}
void circleEraseAfter(Node*& tail, Node* previous) {
    if (tail == nullptr) return;
    Node* victim = previous->next;
    if (victim == previous) tail = nullptr;    // 只剩一个节点：删成空环
    else {
        previous->next = victim->next;
        if (victim == tail) tail = previous;   // 删的是尾：tail 前移
    }
    delete victim;
}

6.7 空环与单节点环 Empty and Single-Node Circles

  • 空环：tail == nullptr。
  • 单节点环：tail->next == tail（自己指向自己）。

先检查 tail 再读 tail->next——否则空环时 tail->next 是空指针解引用。

6.8 释放 clearCircle Releasing a Circular List

void clearCircle(Node*& tail) {
    if (tail == nullptr) return;
    Node* head = tail->next;
    tail->next = nullptr;   // 剪断回边，变成线性
    tail = nullptr;
    clearList(head);        // 复用线性链表的清理
}

先剪断环，把它变回普通线性链表，再复用 clearList。断环 + 复用，一举两得。

6.9 LeetCode 1823 约瑟夫环 Find the Winner of the Circular Game

例题 · 找游戏赢家（LeetCode 1823）

1 到 n 号玩家围成一圈，从当前玩家数起（含自己）数到第 k 个，把第 k 个淘汰；从下一位继续数。问最后剩下谁？n = 5, k = 2 时，淘汰顺序 2 → 4 → 1 → 5，最后 3 号赢。

Node* previous = tail;
while (previous->next != previous) {        // 多于一个节点就继续
    for (int count = 1; count < k; ++count) // 数 k − 1 步
        previous = previous->next;
    circleEraseAfter(tail, previous);       // 删掉第 k 个
}

要点：把当前玩家当 1 数（所以走 k − 1 步）；删除后计数从下一位重新开始；最后把赢家的值存下来、释放最后一个节点再返回。测试 n = 1、k = 1、以及「数过 tail 回绕」的情况。

6.10 LeetCode 141 环形链表（快慢指针） Linked List Cycle

例题 · 检测环（LeetCode 141）

给定 head，判断沿着 next 走是否会再次回到某个节点（即链表里有没有环）。注意：环不一定要回到 head，可能是一条「前缀 + 环」；比较的是节点地址，不是值。

快慢指针（Floyd 判环）：slow 一次走一步，fast 一次走两步。若存在环，fast 最终会「套圈」追上 slow；若无环，fast 会先走到 nullptr。

bool hasCycle(Node* head) {
    Node* slow = head;
    Node* fast = head;
    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;   // 地址相同 = 有环
    }
    return false;                        // fast 走到头 = 无环
}

为什么能追上？因为 fast 每次比 slow 多走一步，环内两者的距离每轮缩小 1，最终必然相遇。这个算法只改自己的局部指针，不动链表本身。

图：快慢指针——slow（绿）一次一步、fast（红）一次两步。若有环，fast 会一圈圈逼近并最终追上 slow；若无环，fast 先到 nullptr。

7.2 哑结点 Dummy Head A Convenient Design

删头节点是链表的「特殊情形」：它没有前驱。若在数据之前人为加一个哨兵节点（dummy head，哑结点），它的值永不用、只是给第一个数据节点提供一个前驱，那么头节点的插入/删除就和其他位置一模一样，无需特判。

Node dummy{0, head};        // 哑结点，值 0 是占位符
Node* p = &dummy;
if (p->next != nullptr) {
    Node* victim = p->next;
    p->next = victim->next;
    delete victim;
}
head = dummy.next;          // 数据从头结点的后继开始

用 p = &dummy 从哑结点出发，第一个数据节点就「有前驱了」。读完记得 head = dummy.next、遍历时跳过 dummy。这是链表题里极常用的技巧（LeetCode 很多题用 dummy 统一头尾处理）。

Part 8 · 总结 Summary

8.1 本讲总结 Summary

  • 链表靠链接保存顺序：单链表、双向链表、循环链表三种表示，支持不同的「到达节点 / 修改节点」方式。
  • 改链接前先保住你还要用的节点：删节点先存后继（savedNext）、反转先存后缀、释放先存 next。
  • 改完检查三件事：端点（head/tail）、结束条件（nullptr 还是回到起点）、每个节点的生命周期（谁负责 delete）。
